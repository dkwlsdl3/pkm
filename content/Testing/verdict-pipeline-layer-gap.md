# 판정이 계층을 넘을 때 계층 사이는 아무도 시험하지 않는다

> **TL;DR**: 판정 결과가 집계기 → 실행기 → 종료 코드처럼 여러 계층을 지날 때, 계층마다 단위 시험이 있어도 **계층 사이의 전달**은 어느 시험도 고정하지 않는다. 전달을 끊는 변이를 넣어 전 시험이 그대로 통과하면 그 구간은 시험이 없는 것이다.

## 증상

- 계층별 단위 시험이 모두 green인데, "이상"으로 판정된 회차가 최종 출력에서 "정상"으로 나온다
- 전달 코드를 일부러 끊어도 시험 결과가 바뀌지 않는다

실측 사례: 판정이 **집계기(상태·판정·종료 코드) → 하네스(완료 기록·종료 코드) → 실행기(정상/이상/신규)** 세 계층을 지나는 구조에서, 아래 세 변이가 각각 회귀 시험 37건과 자체 시험 33건을 **그대로 통과**했다.

```bash
# ① 종료 코드 분기를 상수로 고정
case "$rc" in   →   case "0" in
# ② 완료 기록 직전에 판정을 덮어쓰기
VERDICT=ok
# ③ 실패 반환을 성공 반환으로
return 2   →   return 0
```

셋 다 "조사 필요"를 "정상"으로 바꾼다. 무인 실행이라면 이상을 못 본 채 값만 쌓인다.

## 원인

계층마다 시험을 나눠 쓰면 각 시험은 **자기 계층의 입력을 스스로 만든다.** 그래서 앞 계층이 실제로 무엇을 넘겨주는지, 뒤 계층이 그것을 어떻게 읽는지는 검사 대상에서 빠진다. 계층 수가 늘수록 시험은 늘어나는데 **연결부는 하나도 안 늘어난다.**

여기에 시험이 느슨하면 사각이 겹친다.

| 느슨한 단정 | 통과해 버리는 것 |
|---|---|
| "정상이 아니면 된다" | 빈 값·미계산 값 |
| 파일에 특정 문자열이 있는지 | 그 줄이 주석 처리돼도 통과 |
| 상태 값만 확인 | 상태는 정상인데 판정만 어긋난 회차 |

마지막 줄이 특히 위험하다. 실제로 잡아야 하는 이상은 **상태가 정상인데 판정만 어긋나는 형태**로 오기 때문이다.

## 해결

1. **끝에서 끝까지 한 번에 단언하는 시험을 따로 둔다.** 실제 앞단과 실제 뒷단을 그대로 돌리고, 한 회차에서 판정 값·완료 기록·종료 코드·최종 분류를 **동시에** 확인한다.
2. **역검증한다.** 전달을 끊는 변이를 넣어 몇 건이 실패하는지 세고, 되돌려 전량 통과를 확인한다([[mutation-check-test-effectiveness]]).
3. 값을 정확히 못 박는다. "정상이 아니다"가 아니라 **"정확히 이 판정"**과 **"정확히 이 종료 코드"**를 단언한다.
4. 외부 의존은 최소 stub 으로 대체한다. stub 이 실제와 어긋날 위험보다 **연결을 아무도 안 보는 위험이 크다.**

> stub 함정 둘: 표준입력을 기다리는 명령을 흉내 내면 EOF 를 기다리며 매달린다. 모든 호출에 같은 답을 주면 엉뚱한 조회에도 그 답이 돌아가 파싱이 깨진다.

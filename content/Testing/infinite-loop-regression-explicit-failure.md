# 무한 루프 회귀는 타임아웃이 아니라 명시적 시험 실패로 잡는다

> **TL;DR**: "이 루프가 무한히 돌지 않는다"를 지키려고 시험을 그냥 실행시켜 두면, 회귀했을 때 **시험이 실패하는 게 아니라 멈춘다.** CI 는 타임아웃으로 죽고, 로그에는 어느 시험이 왜 안 끝났는지 안 남는다. **반복 횟수 상한을 시험 안에 두고 초과하면 단언 실패**로 떨어뜨려야 한다.

## 증상

- 회귀가 들어간 뒤 CI 잡이 전체 타임아웃으로 죽는다. 어느 시험인지 특정하려면 로그를 뒤져야 한다.
- 로컬에서는 재현이 안 되거나(빠른 종료 조건이 우연히 맞아서) 터미널이 그냥 먹통이 된다.
- 재실행하면 가끔 통과해서 flaky 로 분류된다.

## 원인

루프 종료 조건을 지키는 시험이 **"끝나면 통과"** 로만 쓰여 있다.

```text
// 회귀하면 여기서 영원히 멈춘다 — 실패가 아니라 정지
process_until_done(&mut state);
assert_eq!(state.processed, 10);
```

시험 러너의 타임아웃은 **인프라 보호 장치**이지 판정 장치가 아니다. 어느 단언이 왜
깨졌는지 말해주지 않으므로, 회귀 원인을 좁히는 데 쓸 수 없다.

## 해결

루프에 **관측 가능한 반복 카운터**를 두고, 시험이 상한을 단언한다.

```text
let mut iterations = 0;
while !state.done() {
    iterations += 1;
    assert!(iterations <= 20, "루프가 20회를 넘겼다 — 종료 조건 회귀");
    step(&mut state);
}
```

- 상한은 **정상 동작의 실제 최대치보다 약간 크게** 잡는다. 너무 빡빡하면 정상 변경에 깨지고, 너무 넉넉하면 회귀를 못 잡는다.
- 바깥 루프만 잠그면 **안쪽 루프의 회귀**는 그대로 통과한다. 중첩 루프는 각각 카운터를 둔다.
- 카운터를 프로덕션 코드에 넣기 싫으면, 루프 본문 호출을 주입 가능한 이음매로 빼고 시험에서 호출 횟수를 센다.

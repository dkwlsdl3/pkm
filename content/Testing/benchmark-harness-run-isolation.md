# 벤치마크 회차 격리 — 라벨 재사용과 측정 겹침이 값을 섞는다

> **TL;DR**: 측정 하네스는 **회차를 물리적으로 격리**해야 한다. 같은 라벨로 다시 돌리면 두 회차가 한 회차로 합쳐지고, 두 측정이 시간상 겹치면 서로의 부하를 잰다. 둘 다 오류 없이 **그럴듯한 값**을 내놓기 때문에 값만 보고는 알 수 없다.

## 증상

- 재측정했더니 회차 수가 예상보다 적거나, 편차가 이유 없이 커졌다
- 같은 조건인데 실행할 때마다 결과가 달라진다
- 결과 디렉터리에 앞 회차와 뒤 회차의 파일이 섞여 있다

## 원인 ① — 라벨 재사용

결과를 라벨(조건 이름) 단위 디렉터리에 쌓는 하네스에서, **같은 라벨로 다시 돌리면 이전 회차 위에 덧쌓인다.** 집계기는 디렉터리의 파일을 전부 읽으므로 **두 회차가 한 회차로 평균된다.**

특히 나쁜 조합: 앞 회차는 정상, 뒤 회차는 조건을 바꿔 돌린 경우. 서로 다른 조건의 값이 한 평균에 들어가고, 그 평균은 **어느 조건도 아닌 값**이 된다.

## 원인 ② — 측정 겹침

여러 세션·여러 창에서 측정을 돌리면 두 측정이 겹친다. 겹치면 각자가 상대의 부하를 자기 조건의 결과로 기록한다. 사람이 관리하면 반드시 일어난다 — 실제로 **하루에 세 번** 겹친 사례가 있다.

## 원인 ③ — 실패가 성공으로 기록됨

계측기 시작이 실패했는데 종료 코드가 0이면, 하네스는 **계측 없이 측정을 진행하고 정상 종료로 기록한다.** 나중에 보면 결과 파일만 비어 있다.

## 해결

```bash
# ① 회차 단위 격리 — 라벨 아래에 실행 식별자를 한 겹 더 둔다
RUN_DIR="$RESULTS/$LABEL/run-$(date +%Y%m%dT%H%M%S)"
mkdir -p "$RUN_DIR"      # 기존 회차를 절대 건드리지 않는다

# 라벨이 이미 있으면 접두어로 갈라 둔다 (덮어쓰기·병합 금지)
#   before-fix/… , after-fix/…

# ② 겹침 차단 — 락 파일로 동시 실행을 거부한다
exec 9>"$LOCK" || exit 1
flock -n 9 || { echo "다른 측정이 진행 중이다 — 거부"; exit 1; }

# ③ 계측기 시작 실패를 종료 코드로 전파
start_probe || { echo "계측기 시작 실패"; exit 1; }
#    성공 판정은 "명령이 돌아왔다"가 아니라 "산출물이 생겼다"로 한다
test -s "$RUN_DIR/probe.out" || exit 1
```

## 주의

> [!WARNING]
> 이 세 가지는 모두 **오류 없이 틀린 값**을 만든다. 측정은 정상 종료되고 숫자도 그럴듯하다. 그래서 결과 검토로는 못 잡고, **하네스 쪽에서 구조적으로 막아야 한다.**

측정 전에 확인할 것: 이 라벨로 이전에 돈 적이 있는가 · 지금 다른 측정이 도는가 · 계측기가 실제로 파일을 쓰고 있는가.

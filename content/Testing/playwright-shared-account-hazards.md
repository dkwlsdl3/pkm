# Playwright Shared Account Hazards

> **TL;DR**: 공유 계정을 변경하는 E2E는 테스트가 통과해도 다음 테스트와 개발 환경을 망가뜨릴 수 있으므로 전용 계정, 복구 경로, 잠금 카운터 정리가 필요하다.

---

## 개요

- **무엇인가**: Playwright E2E가 dev/admin 같은 공유 계정의 비밀번호, 권한, 정책, 프로필 상태를 바꾸면서 환경을 오염시키는 문제.
- **왜 쓰는가**: 상태 변경 테스트를 무조건 금지하기보다, 어떤 조건에서 안전하게 실행할 수 있는지 기준을 잡기 위해.
- **언제 쓰는가**: 비밀번호 변경, 회원가입, 로그인 정책 변경, 관리자 권한 변경처럼 다른 테스트의 로그인/권한 전제에 영향을 주는 케이스를 만들 때.

---

## 핵심 개념

### 공유 계정은 테스트 fixture가 아니다

공유 dev/admin 계정은 여러 spec과 사람의 수동 확인이 동시에 기대하는 환경 전제다. 이 계정의 비밀번호나 정책을 바꾸는 테스트는 실패했을 때뿐 아니라 성공했을 때도 후속 테스트를 깨뜨릴 수 있다.

### 원복 실패도 상태 오염이다

비밀번호 변경 테스트에서 원복을 API로 수행하려면 현재 비밀번호, 새 비밀번호 정책, 로그인 잠금 정책이 모두 맞아야 한다. 원래 dev 비밀번호가 현재 정책을 만족하지 않는 경우처럼 시드/DB로만 가능한 상태는 API 원복이 막힐 수 있다.

### 잠금 카운터까지 복구해야 한다

잘못된 원복 시도는 로그인 실패 횟수를 누적한다. 비밀번호만 되돌려도 계정 잠금 테이블이 남아 있으면 다음 로그인은 계속 실패할 수 있다.

---

## 코드 / 사용 예시

```ts
test.skip(true, '공유 admin 계정 비밀번호를 변경하므로 전용 테스트 계정이 생길 때까지 비활성화');
```

```sql
-- dev/test 복구 패턴 예시: 실제 값은 환경 변수나 secret에서 주입
UPDATE auth_users
SET password_hash = '<argon2id-phc>'
WHERE email = '<admin-email>';

DELETE FROM auth_login_attempts
WHERE email = '<admin-email>';
```

---

## 주의사항

> [!WARNING]
> 공유 계정 비밀번호 변경 테스트는 `afterEach` 원복만으로는 부족하다. 테스트 프로세스가 중간에 죽거나 로그인 잠금이 누적되면 원복 코드 자체가 실행되지 않거나 실패한다.

- 전용 계정을 만들 수 없으면 skip 처리한다.
- 원복은 "비밀번호 복구"와 "잠금 카운터 정리"를 같이 다룬다.
- 테스트 계정의 초기 비밀번호는 현재 서비스의 비밀번호 정책을 만족해야 한다.
- 성공/실패 경로 모두에서 fixture 정리가 되는지 확인한다.

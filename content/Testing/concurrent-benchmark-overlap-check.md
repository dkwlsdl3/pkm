# min·max 구간은 동시성의 증거가 아니다 (다중 클라이언트 집계)

> **TL;DR**: 여러 대가 동시에 부하를 걸었다고 집계하려면 **구간이 실제로 겹쳐야** 한다. 시작을 `min`, 종료를 `max`로 잡으면 그것은 합집합이라 **하나도 안 겹쳐도 시간이 채워진다.** 겹침을 **교집합**으로 계산해 비율로 남기고, 임계 미만이면 무효 처리한다.

---

## 증상

클라이언트 3대의 대역폭을 합산해 "동시 부하 시 총 처리량"으로 보고했는데, 실제로는 한 대가 끝난 뒤 다음 대가 시작한 회차가 섞여 있었다. 집계 결과에는 아무 표시도 없다.

## 원인

집계 스크립트가 흔히 쓰는 형태:

```python
start = min(h.start for h in hosts)   # 합집합의 시작
end   = max(h.end   for h in hosts)   # 합집합의 끝
total = sum(h.bytes for h in hosts) / (end - start)
```

`min`~`max`는 **합집합**이다. 세 대가 순차적으로 돌아도 이 구간은 채워지고, 총량을 그 시간으로 나누면 그럴듯한 숫자가 나온다. **동시성을 검증한 곳이 어디에도 없다.**

## 해결

### 1. 교집합으로 겹침률을 낸다

```python
overlap_start = max(h.start for h in hosts)   # 교집합
overlap_end   = min(h.end   for h in hosts)
overlap = max(0, overlap_end - overlap_start)
ratio   = overlap / (max_end - min_start)     # 합집합 대비 겹친 비율
```

- 겹침률을 **결과 표의 열로 남긴다.** 사후에 어느 회차가 얼마나 겹쳤는지 확인할 수 있어야 한다
- **임계(예: 80%) 미만이면 무효**로 뺀다

### 2. 상한 검사를 함께 건다

- **호스트별 값이 회선 상한을 넘으면** 물리적으로 불가능하다 → 무효 (캐시가 부풀린 값이다)
- **겹침률이 100%를 넘으면** 정의상 불가능하다 → 시각 데이터 비정합이다. 클라이언트와 서버의 **시간대(TZ)가 다르면** 여기서 드러난다

### 3. 무효면 합계를 출력하지 않는다

무효 표시만 달고 값을 살려 두면 안 된다.

> 인용될 때 **표시만 떨어져 나간다.** 표에서 한 줄을 복사하는 사람은 각주를 함께 가져가지 않는다.

### 4. 실패한 호스트의 `0`을 합에서 뺀다

한 대가 중간에 죽으면 그 호스트는 `0`을 남긴다. 그대로 합산하면 **분자는 2대인데 분모는 3대분**이 되어 "저장 계층에 여유가 있다"는 정반대 판단으로 이어진다. **호스트 실패 시 그 회차 전체를 무효**로 한다.

# 계약을 소스 파싱으로 판정하는 시험은 분석기가 된다

> **TL;DR**: "이 함수를 반드시 거쳐야 한다", "이 호출을 잠금 안에서 해야 한다" 같은 계약을 **소스 코드를 읽어** 판정하는 가드 시험은, 계약이 지켜지는지가 아니라 **코드가 예상한 모양인지**를 본다. 위임 함수 하나만 끼워도 오탐이 나고, 그 오탐이 곧 배포 차단이다. 계약은 **주입 가능한 경계를 만들어 실행으로** 지킨다.

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| 가드 시험 | guard test | 규칙 위반을 막으려고 둔 검사용 시험. 기능이 아니라 규약을 본다 |
| AST | Abstract Syntax Tree | 소스를 파싱해 만든 구문 트리. 코드를 데이터로 훑을 때 쓴다 |
| 주입 | dependency injection | 외부 호출부를 인자로 받게 해서 시험이 가짜 구현을 끼울 수 있게 하는 것 |

## 증상

- 계약을 바꾸지 않았는데 **리팩터링만으로 가드가 깨진다**. 본체를 파일 둘로 나눴더니 가드 넷이 통째로 실패.
- 가드가 **위임 함수를 원래 호출로 착각**해 통과시키거나, 반대로 정상 코드를 위반으로 잡는다.
- 특수 케이스를 하나씩 더해 가드를 키우게 된다. 리뷰에서 반례가 나올 때마다 예외 분기가 늘어난다.
- 결과적으로 **배포가 계약 위반이 아니라 분석기 오탐으로 막힌다.**

## 원인

소스를 파싱하는 순간 그 시험은 "계약 검사"가 아니라 **데이터 흐름 분석기**가 된다. 분석기는 언어의 문법이 허용하는 만큼 경우의 수가 있고, 끝이 없다. 호출을 한 겹 감싸거나, 매크로로 생성하거나, 트레이트 뒤로 숨기면 같은 계약이 전혀 다른 텍스트가 된다.

핵심은 **판정 대상이 계약이 아니라 코드의 모양**이라는 것이다. 코드 모양은 계약을 지키면서도 얼마든지 달라질 수 있다.

## 해결

계약을 **실행할 수 있는 형태로** 만든 다음, 실행 시험으로 지킨다.

1. **경계를 한자리로 모은다.** 프로비저닝이 건드리는 호스트 명령, 파일 쓰기, 포트 개방 같은 외부 효과를 각 호출부에 흩어 두지 말고 주입 가능한 인터페이스 뒤로 모은다.
2. **가짜 구현을 끼워 실제로 돌린다.** 안전장치를 우회하면 가짜 구현이 "호출당했다"고 기록하고 시험이 실패한다. 계약이 코드 모양과 무관해진다.
3. **정적 검사는 역할을 줄여서 남긴다.** 계약 판정은 포기하고, **금지된 표기가 등장하는지**만 본다(예: 특정 API 이름, 위험한 리터럴). 문자열 존재 검사는 오탐이 적고 의미도 분명하다.
4. 계약 대체 전에는 **무엇이 실행으로 안 지켜지는지** 먼저 목록화한다. 가드를 지우고 나서 빈자리를 찾으면 늦다.

```text
// 전 — 소스를 읽어 판정 (오탐 원천)
assert!(source_of("provision.rs").contains("ensure_safety_check("));
   ↳ 위임 함수 safe_provision() 을 만들면 실패. 계약은 그대로인데.

// 후 — 경계를 주입해 실행으로 판정
let spy = SpyHostOps::new();
provision(&spy, plan).unwrap();
assert!(spy.called("ensure_safety_check"));   // 어떤 모양으로 부르든 호출되면 통과
```

> [!WARNING]
> **정적 분석 자체가 금지는 아니다.** 라우트 인벤토리처럼 "소스에서 목록을 뽑는" 용도는 정당하다 → [[route-inventory-syn-ast]]. 문제는 **목록 추출**이 아니라 **계약 판정**에 쓸 때다. 추출은 결과를 사람이 검토하지만, 판정은 자동으로 배포를 막는다.

> [!WARNING]
> 리뷰에서 반례가 나올 때마다 분석기에 특수 케이스를 더하는 것은 **접근을 바꿔야 한다는 신호**다. 케이스가 세 번 늘면 실행 시험으로 옮길 때다.

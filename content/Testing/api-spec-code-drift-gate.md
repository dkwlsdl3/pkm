# API 스펙-코드 대조 게이트는 파서가 못 읽은 라우트를 통과시킨다

> **TL;DR**: 저장소에 OpenAPI 스펙을 고정하고 "코드와 다르면 CI 실패"를 걸어도, 대조가 **라우트 애노테이션을 긁는 방식**이면 애노테이션이 없는 라우트는 대조 집합에 아예 들어오지 않는다. 게이트는 초록인데 인증이 필요한 경로가 검사망 밖에 남는다. **파서가 읽지 못한 등록을 개수로 드러내고**, 실제 라우터 등록과 대조하라.

---

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| OpenAPI 스펙 | OpenAPI Specification | HTTP API의 경로·파라미터·응답을 기계가 읽는 형식으로 적은 문서 |
| 드리프트 | drift | 문서와 실제 코드가 시간이 지나며 어긋나는 것 |
| 애노테이션 | annotation | 함수 위에 붙여 스펙 생성기에 정보를 주는 표기(`#[utoipa::path(...)]`, `@Operation` 등) |
| 라우터 등록 | route registration | 경로와 핸들러를 실제로 연결하는 코드 |

## 왜 스펙을 고정하나

스펙을 생성만 하고 저장소에 두지 않으면, 프론트가 보는 문서와 백엔드 코드가 갈려도 아무도 모른다. 스펙 파일을 커밋하고 **생성 결과와 다르면 CI가 실패**하게 걸면, 코드를 고치면서 스펙을 갱신하지 않는 일이 막힌다.

여기까지는 잘 알려져 있다. 문제는 그다음이다.

## 증상 — 게이트를 넣었는데 뚫린다

- 스펙 게이트가 계속 초록인데, 문서에 없는 종단점이 배포돼 있다.
- 인증 미들웨어가 안 걸린 경로가 스펙에도 없고 대조에도 안 걸린다.
- 게이트를 끄려고 넣은 환경 변수 값에 오히려 게이트가 켜진다(값 파싱이 "존재 여부"만 본다).
- 존재하지 않는 URL을 스펙에 적어도 통과한다(대조가 한쪽 방향만 본다).

## 원인 — 대조 집합이 이미 새고 있다

스펙 생성기는 대개 **애노테이션이 붙은 핸들러만** 수집한다. 그래서 대조는 이렇게 된다.

```text
스펙에 있는 경로 집합   = 애노테이션이 붙은 것들
코드에서 뽑은 경로 집합 = 애노테이션이 붙은 것들   ← 같은 출처다
→ 둘은 항상 일치한다. 애노테이션이 없는 라우트는 양쪽 모두에 없다.
```

같은 출처를 두 번 읽고 "일치한다"고 말하는 구조다. 게이트가 담보하는 명제는 "애노테이션끼리 일치한다"이지 "API가 문서와 같다"가 아니다.

파서가 문법을 못 읽어 건너뛴 등록도 같은 방식으로 사라진다. 조용히 빠지고, 빠진 사실이 어디에도 남지 않는다.

## 해결

**하나. 대조의 한쪽은 반드시 실제 라우터 등록에서 가져온다.** 애노테이션이 아니라 라우터를 구성하는 코드(또는 런타임에 등록된 경로 목록)를 기준 집합으로 삼는다. 두 집합의 출처가 달라야 대조가 성립한다.

**둘. 파서가 못 읽은 등록을 개수로 드러낸다.** "N개 등록 중 M개를 읽었다"를 출력하고, `N ≠ M`이면 실패시킨다. 조용한 누락을 시끄러운 실패로 바꾸는 것이 요점이다.

**셋. 실측 건수를 기준선으로 박아 둔다.** 다만 개수만으로는 삭제+추가에 뚫린다 — 집합과 내용으로 계약해야 한다([[count-comparison-is-not-a-freeze-gate]]).

**넷. 게이트의 on/off 판정을 값으로 읽는다.** 환경 변수의 **존재 여부**로 켜면 `FLAG=0`, `FLAG=false`에도 켜진다.

**다섯. 양방향으로 본다.** 코드에 없는데 스펙에만 있는 경로도 실패여야 한다. 한 방향만 보면 거짓 URL이 문서에 남는다.

## 확인 방법

게이트를 믿기 전에 **일부러 깨 본다**. 애노테이션 없는 라우트를 하나 추가하고 CI가 빨개지는지, 스펙에 없는 URL을 넣고 실패하는지 확인한다. 깨도 초록이면 그 게이트는 장식이다([[mutation-check-test-effectiveness]]).

단, 여럿이 공유하는 작업 트리에서 파일을 깨뜨렸다 되돌리는 방식은 쓰지 않는다 — 그사이 다른 세션이 깨진 상태를 읽는다. 별도 브랜치나 임시 작업 트리에서 한다.

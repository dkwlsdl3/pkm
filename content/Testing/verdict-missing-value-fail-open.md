# 판정 값이 비면 통과시키는 fail-open

> **TL;DR**: "이상이면 막는다"로 짠 검사는 **판정이 아예 없는 경우를 통과시킨다**. 없음과 정상은 다른 상태다. 검사는 "이상이면 막는다"가 아니라 **"정상임이 확인되지 않으면 막는다"**로 써야 한다.

## 증상

- 검사 코드는 멀쩡한데, 판정 열이 **빈 산출물**이 정상으로 통과한다
- 그 산출물만으로는 회차를 인증할 수 없는데도 후속 처리에 섞여 들어간다

```python
# fail-open — 값이 없으면 조건이 거짓이라 그냥 통과
if verdict == 'INVESTIGATE':
    block()

# fail-closed — 정상임이 확인된 것만 통과
if verdict != 'OK':
    block(reason='판정 없음' if not verdict else '조사 필요')
```

## 원인

판정이 비는 경로는 **정상 경로에서는 안 보인다.** 실측 사례에서는 집계를 예상값 인자 없이 다시 돌리면 판정이 계산되지 않아 그 열이 비었다. 원자료는 멀쩡하니 산출물은 정상처럼 보이고, 검사는 "이상"이라는 문자열만 찾으므로 아무것도 걸리지 않았다.

즉 **재처리·재집계·부분 실행**이 fail-open 을 실제 상태로 만든다. 처음 만들 때 존재하지 않던 상태가 운영 중에 생긴다.

## 해결

- **없음과 이상을 갈라 표시한다.** 원인이 다르므로 사람이 볼 곳도 다르다 — 없음은 처리 과정의 문제, 이상은 대상의 문제다.
- 검사 대상 범위를 명시한다. 판정을 남기지 않는 행(집계 대상이 아닌 보조 행)까지 검사하면 정상 건이 걸린다. 실측에서는 검사를 넣자마자 그렇게 걸렸고 시험이 잡았다.
- **판정이 비는 재처리 절차를 문서에 남긴다.** 재집계할 때 어떤 인자를 함께 줘야 판정이 남는지 적어 두지 않으면 같은 상태가 반복 생성된다.
- 이 결함은 **적대적 검토로도 잘 안 잡힌다.** 코드를 공격하는 시선은 "틀린 값"을 찾지 "없는 값"을 찾지 않는다. 실제로 발견은 산출물의 시각과 빈 열을 대조하다 나왔다 — **산출물 자체를 훑는 점검**이 따로 필요하다.

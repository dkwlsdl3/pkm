# 스토리지 레이턴시 백분위수 읽기 (avg/p95/p99/CoV)

> **TL;DR**: 평균만 보면 꼬리 지연을 놓친다 — avg → p95 → p99 → p99.9 → max 순으로 읽고, CoV 급등은 조건 오염부터 의심한다.

---

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| avg | average | 평균 |
| p50 | 50th **percentile** (백분위수) | 절반이 이 값보다 빠름 = 중앙값(median) |
| p95 | 95th percentile | 95%가 이 값보다 빠름 = 느린 5%의 경계선 |
| p99 | 99th percentile | 99%가 이 값보다 빠름 = 느린 1%의 경계선 |
| p99.9 | 99.9th percentile | 1000번에 1번 나오는 느린 케이스 |
| max | maximum | 가장 느렸던 한 건 |
| CoV | **C**oefficient **o**f **V**ariation (변동계수) | 표준편차 / 평균 |

`p<숫자>`는 측정값을 **빠른 순으로 정렬했을 때의 위치**를 가리킨다. 요청 1000건이면 p95는 950번째, p99는 990번째, p99.9는 999번째 값이다. 뒤로 갈수록 더 극단적으로 느린 소수를 보는 것이고, 이 구간을 **꼬리 지연(tail latency)** 이라 한다.

"느린 1%는 무시해도 되지 않나"가 아니다. 화면 하나가 요청 100건을 부르면 그중 하나라도 p99에 걸릴 확률은 1 − 0.99¹⁰⁰ ≈ **63%**다. p99는 드문 예외가 아니라 사용자가 흔히 겪는 값이다.

## 레이턴시 읽는 순서

- avg → p95 → p99 → p99.9 → **max** 순으로 확인한다. 평균은 문제를 숨긴다.
  - 예: 999회 1ms + 1회 235초 → 평균 236ms(= (999×1 + 235,000) ÷ 1000)로 무해해 보이지만 사용자 1명은 235초 hang
  - **avg > p99 역전** = 단발성 극단 이상치 신호 (max만 봐선 놓침)
    - 위 예시가 그 경우다. p99는 990번째 값이라 1ms인데 평균은 236ms. 정상 분포면 평균은 p99보다 작다 — 역전됐다면 상위 1% 안에 평균을 끌어올릴 만큼 큰 값이 있다는 뜻이다. "전반적으로 느림"이 아니라 "어쩌다 한 번 멈춤"으로 진단이 갈린다.

## CoV (변동계수)

- CoV = 표준편차/평균. 반복 측정 간 흔들림 정도를 나타낸다.
- 평균에 대한 **비율**이라 단위가 없다. 그래서 규모가 다른 측정끼리 비교할 수 있다.
  - 평균 10ms·표준편차 1ms → CoV 0.1 / 평균 100ms·표준편차 10ms → CoV 0.1 (흔들림의 절대 크기는 10배지만 상대적으로는 같음)
  - 표준편차만 비교하면 평균이 큰 쪽이 늘 불안정해 보인다.
- 측정 조건이 작거나 캐시/drop 타이밍이 과격해도 CoV가 커질 수 있음 → CoV만으로 "불안정"이라 단정하지 않는다.

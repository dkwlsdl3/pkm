# 권한으로 실패를 만드는 시험은 root 러너에서 판별력이 0 이 된다

> **TL;DR**: `chmod 000` 으로 읽기 실패를 만들어 방어를 시험하면, **root 는 파일 권한을 무시하고 그냥 읽으므로** 조건이 성립하지 않는다. 그러면 시험은 조건 실패와 제품 결함을 구별하지 못하고 **없는 결함을 보고**하거나 **조용히 통과**한다. 실패 조건은 계정에 의존하지 않는 수단(스텁·주입)으로 만들어라.

## 증상

- 로컬에서는 30/30 통과인데 CI 러너에서 29 통과·1 실패가 난다.
- 실패 문구가 `집계 판정이 죽었는데 채택 가능이 났다` 처럼 **제품의 fail-open 처럼 보인다.** 실제로는 파일을 못 읽게 만들려던 조건이 성립하지 않아 게이트가 정상 통과한 것이다.
- 같은 부류의 다른 시험은 조기 `return` 으로 **조용히 skip** 돼 아무도 눈치채지 못한다.

## 원인

root 는 `DAC_OVERRIDE` 능력을 가지므로 파일 모드를 무시한다. 실측으로 `chmod 000` 한 파일을 `cat` 과 `python3` 둘 다 읽었다.

문제의 핵심은 root 자체가 아니라 그 한 겹 안쪽이다.

> **시험이 "만들려던 조건이 실제로 성립했는지"를 확인하지 않으면, 조건 실패와 제품 결함이 같은 결과로 보인다.**

방향은 둘 다 나쁘다.

| 형태 | 증상 | 왜 나쁜가 |
|---|---|---|
| 조기 return 으로 skip | 조용히 통과 | 방어가 사라져도 초록 |
| 조건 미성립인데 실패 판정 | 거짓 실패 | 없는 결함을 보고하고, **진짜 fail-open 이 생겨도 구별 안 됨**(판별력 0) |

## 해결

방어가 실제로 잡는 것이 무엇인지 다시 보고, 그 상황을 **계정과 무관한 수단**으로 만든다. 아래 예에서 방어가 잡는 것은 "권한이 없다"가 아니라 **"집계 프로그램이 끝까지 못 돌았다"** 이다.

```bash
# ❌ root 에서는 조건이 성립하지 않는다
chmod 000 "$D5/summary.csv"
rc=$(run_gate "$D5")

# ✅ 실패하는 스텁을 PATH 앞에 둔다 — 계정과 무관하게 성립한다
mkdir -p "$TMP/failbin"
printf '#!/usr/bin/env bash\nexit 1\n' >"$TMP/failbin/python3"
chmod +x "$TMP/failbin/python3"
rc=$(PATH="$TMP/failbin:$PATH" "$GATE" "$D5" >"$TMP/out.$$" 2>&1; echo $?)
```

- 수정 후 로컬·CI 러너 **양쪽 30/30** 이 되고, 방어 코드를 무력화하면 **그 시험만 정확히 실패**한다(역검증).
- 스텁을 쓸 수 없다면 최소한 **조건 성립을 먼저 검사하고, 안 되면 skip 을 명시**해라. 조용한 skip 은 금지다.

> [!WARNING]
> 이 계열 시험은 **역검증(방어를 지우면 깨지는가)** 을 반드시 붙여라. 조건이 성립하지 않는 환경에서는 시험이 늘 통과하거나 늘 실패하는데, 둘 다 "재고 있는 게 없다"는 뜻이다 → [[mutation-check-test-effectiveness]]

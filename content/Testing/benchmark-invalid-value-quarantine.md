# 무효값에 표시만 달면 인용될 때 표시가 떨어져 나간다

> **TL;DR**: 측정 문서에서 "이 값은 무효"라는 각주는 발췌되는 순간 사라진다. **금지 목록을 문서 맨 앞**에 두고, **결론 문장 안에 잣대(기준·단위·조건)를 병기**한다 — 결론이 가장 많이 발췌되는 자리다.

---

## 왜 필요한가

긴 측정 문서의 숫자는 그 문서 안에서 소비되지 않는다. **표에서 한 줄, 결론에서 한 문장이 잘려 나가** 보고서·메일·영업 자료로 옮겨진다. 이때 따라가지 않는 것:

- 표 아래 각주 ("※ 이 회차는 무효")
- 값 옆의 조건 라벨 (측정 조건·표본 수)
- 어느 계층에서 잰 값인지 (애플리케이션 값 vs 디스크 트래픽)

## 실제로 반복되는 실패

**작성자 자신이 자기 금지 목록을 위반한다.** 문서 앞에 "이 값은 인용 금지"라 적어 놓고 본문 표에서 그 값을 쓰는 일이 한 문서 안에서 세 번 반복된 사례가 있다. 사람이 게을러서가 아니라, **금지 목록과 본문이 멀리 떨어져 있으면 본문을 쓸 때 목록이 보이지 않기** 때문이다.

## 방법

### 1. 금지 목록을 문서 맨 앞에

"쓰면 안 되는 숫자" 목록을 요약 바로 다음에 둔다. 각 항목에 **왜 무효인지**를 한 줄로 적는다.

### 2. 결론 문장에 잣대를 병기

```
나쁨:  풀을 2배로 늘리면 730 MB/s 까지 나온다
좋음:  풀을 2배로 늘리면 730 MB/s (디스크 트래픽 기준, 패리티 포함) —
       같은 잣대의 애플리케이션 값은 428 MB/s
```

표에만 라벨을 달고 결론 문장에서 빼면, **가장 많이 발췌되는 자리에서 라벨이 사라진다.** 위 예에서 잣대가 떨어지면 1.7배 부풀려진 값이 그대로 돌아다닌다.

### 3. 무효면 합계를 계산하지 않는다

무효 판정된 회차를 "표시만 달고" 합산에 넣지 않는다. → [[concurrent-benchmark-overlap-check]]

### 4. 상한·하한을 뒤집어 쓰지 않는다

"풀 2개에서 487 MB/s"는 풀 4개를 안 쟀다면 **하한**이다. 상한으로 쓰면 "이보다 더 못 낸다"는 반대 의미가 된다.

### 5. 표본 수와 조건을 값 옆에

`348 MB/s` 가 아니라 `348 MB/s (3대 균등 배정, n=2)`. 표본이 2인 값과 10인 값이 같은 표에 라벨 없이 나란히 있으면 안 된다.

# feature 를 끄면 시험은 실패하지 않고 침묵한다

> **TL;DR**: 조건부 컴파일(`#[cfg(feature = "…")]`)로 감싼 시험은 feature 가 꺼진 빌드에서 **애초에 존재하지 않는다.** 스킵으로 표시되지도 않으므로 요약줄에 흔적이 없다. 실제로 DB 시험 52건이 이 방식으로 조용히 잠들어 있었다. **시험이 도는지 자체를 검사하는 시험**이 없으면 알 수 없다.

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| feature | cargo feature | 빌드 시점에 켜고 끄는 컴파일 옵션. 꺼지면 해당 코드가 아예 컴파일되지 않는다 |
| 조건부 컴파일 | conditional compilation | `#[cfg(...)]` 로 코드 포함 여부를 빌드 시점에 결정하는 것 |
| 스킵 | skipped | 시험 러너가 "있지만 안 돌렸다"고 보고하는 상태. 조건부 컴파일은 여기에도 안 잡힌다 |

## 증상

- CI 는 초록이고 시험 요약줄도 정상인데, 특정 영역의 회귀가 전혀 잡히지 않는다.
- 로컬에서 같은 명령을 돌리면 시험 수가 CI 와 다르다. 아무도 그 차이를 세지 않았다.
- 새로 추가한 시험이 "통과"로 보이지만, 실은 그 빌드에서 컴파일조차 되지 않았다.

## 원인

스킵과 부재는 다르다.

| | 러너 보고 | 알아챌 수 있나 |
|---|---|---|
| 런타임 스킵(`ignore`, 조건 분기) | `skipped` 로 집계 | 요약줄에 보인다 |
| **조건부 컴파일 제외** | **집계 자체에 없음** | **총 시험 수를 세지 않으면 모른다** |

DB 를 쓰는 시험을 `#[cfg(feature = "db-tests")]` 로 감싸두고 CI 잡 하나가 그 feature 를 빠뜨리면, 그 잡은 해당 시험이 없는 채로 초록이 된다. 시험을 **추가**할 때는 아무도 이 조건을 다시 확인하지 않는다.

## 해결

```text
1) 시험이 도는지를 시험한다
   - 기대 시험 수 / 기대 모듈이 실행 목록에 있는지 확인하는 메타 시험을 둔다
   - 또는 feature 가 꺼진 빌드에서 "이 영역은 커버되지 않는다"를 명시적으로 실패시킨다

2) feature 조합을 CI 가 전부 돈다는 것을 고정한다
   - 잡마다 어떤 feature 로 도는지 한 자리에 적고, 그 표를 계약시험이 읽게 한다

3) 시험 수를 요약에서 기록한다
   - 잡별 실행 건수를 남겨 두면 갑자기 줄었을 때 눈에 띈다
```

> [!WARNING]
> **"시험이 없는 것"은 "시험이 실패한 것"보다 위험하다.** 실패는 누군가 보지만 부재는 아무도 안 본다. 같은 이유로 선택 규칙이 0건을 매치해도 통과로 보인다 → [[test-selection-zero-match]]

> [!WARNING]
> 조건부 컴파일을 **없애라는 뜻은 아니다.** DB·libvirt 처럼 환경이 필요한 시험은 갈라야 한다. 갈라 두되, **갈린 쪽이 어딘가에서는 반드시 돈다**는 것을 검사로 고정하라는 뜻이다.

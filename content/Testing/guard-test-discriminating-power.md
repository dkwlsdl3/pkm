# 가드를 지웠을 때 red 가 나오는지로 시험을 잰다

> **TL;DR**: green 인 시험은 "코드가 맞다" 를 증명하지 않는다. 증명하는 것은 **막으려던 가드를 빼면 그 시험이 red 로 바뀐다**는 확인뿐이다. 판별력 없는 시험은 통과 개수만 늘리고 아무것도 지키지 않는다.

## 개요

- **무엇**: 새로 쓴 시험이 실제로 무언가를 **판별하는지** 확인하는 절차. 변이 시험(mutation testing)의 손으로 하는 최소판이다
- **왜 / 언제**: 보안 가드, 권한 검사, 동시성 잠금, 상태 전이 제약처럼 **"막는 것" 이 목적인 코드**에 시험을 붙였을 때. 이런 시험은 성공 경로만 밟고도 쉽게 green 이 된다

## 동작 / 예시

```bash
# 1. 시험이 green 인 것을 확인
cargo test --test session_revoke_others

# 2. 가드를 일부러 무력화한다 (조건 반전, 검사 줄 주석 처리)
#    - 잠금 획득을 지운다
#    - 권한 검사 if 를 통째로 뺀다
#    - 상태 전이 조건을 always-true 로

# 3. 다시 돌린다 — 여기서 red 가 나와야 그 시험에 판별력이 있다
cargo test --test session_revoke_others   # 기대: FAILED

# 4. 가드를 되돌린다 (반드시)
git checkout -- src/...
```

3번에서 **여전히 green 이면 그 시험은 가드를 검증하지 않는다.** 흔한 원인:

- 시험이 **결과가 아니라 표시**를 본다 — "폐기됨 이라고 적혔는가" 만 보고, 폐기된 토큰으로 실제 요청이
  거부되는지는 안 본다
- 시험이 **성공 경로만** 밟는다. 막혀야 하는 입력을 아예 안 넣는다
- 단언이 너무 느슨하다 (`assert!(result.is_ok())` 만 있고 내용을 안 본다)
- 시험이 조용히 **건너뛰어지고 있다** (`#[ignore]`, 환경변수 없어서 skip)

## 주의

> [!WARNING]
> 4번(되돌리기)을 빠뜨리면 가드가 빠진 채 커밋된다. 워킹 트리에서만 하고, 확인 직후 즉시 되돌린다.
> 커밋 전 `git diff` 로 가드가 제자리인지 확인할 것.

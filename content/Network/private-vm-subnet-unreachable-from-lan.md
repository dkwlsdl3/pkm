# 사설 대역 VM에 사내망 PC가 닿지 않는다

> **TL;DR**: 서버 안의 사설 대역 VM에 사내 PC가 접속하지 못할 때, VM에 "돌아가는 길"(반환 경로)만 넣어서는 해결되지 않는다. 사내 PC의 패킷은 그 사설 대역을 모르는 사내 게이트웨이로 가서 **상위 장비 쪽으로 빠져 버린다.** 서버까지 오지도 않는다. 먼저 traceroute와 서버 쪽 패킷 캡처로 **패킷이 서버에 도착하는지**부터 확인한다. 그다음 세 가지 해법 중 하나를 고른다.

## 증상

- 서버 호스트에서는 VM에 잘 닿는데, 같은 사내망의 다른 PC에서는 접속이 안 된다.
- VM에 사내망 대역으로 가는 경로를 추가해도 그대로다.

## 원인

```text
사내 PC ──> 사내 게이트웨이 ──> (사설 대역 모름) ──> 상위 장비로 기본 경로 전달 ──> 소멸
                   ✗ 서버(호스트) 쪽으로는 안 감
```

- 사설 대역은 서버 호스트 안에만 있는 망이다. 사내 라우터는 그 대역을 모른다.
- 반환 경로는 "서버까지 온 패킷"에 대한 답장 길이다. **오는 길이 없으면** 쓸모가 없다.

## 해결

진단:

```bash
traceroute <VM_PRIVATE_IP>                  # 사내 PC에서: 게이트웨이 다음이 어디로 가나
tcpdump -ni <HOST_LAN_IF> host <PC_IP>      # 서버에서: 패킷이 오기는 하나
```

해법(위에서부터 권한이 적게 듦):

| 방법 | 필요한 것 | 비고 |
|---|---|---|
| 사내 라우터에 정적 경로 추가(사설 대역 → 서버 호스트) | 네트워크 관리 권한 | 가장 깔끔. 관리 주체가 다르면 요청이 필요 |
| 터널·포트 포워딩(NAT) | 서버 권한 | 프로토콜이 특정 포트·출발 포트를 쓰면(예: Lustre) 까다로움 |
| **VM에 사내망 IP 추가**(브리지) | 서버 권한 + 사내 IP 할당 | 실제로 선택한 방법. VM 5대에 사내망 NIC 추가 |

브리지 변경은 원격 접속을 끊을 수 있다. **자동 원복 장치**를 걸고 한다. 실제 작업은 NetworkManager 체크포인트를 썼다. 정해진 시간 안에 확정하지 않으면 이전 설정으로 되돌아간다. 첫 적용 때 SSH가 끊겼지만 자동 원복으로 복구됐다.

```bash
# 같은 일을 nmstate 로 할 때(이 환경에서 직접 실행해 보지는 않음 — 판의 --help 확인)
nmstatectl apply --no-commit --timeout 120 bridge.yml
nmstatectl commit          # 접속이 살아 있으면 확정
```

- 본딩 위에 브리지를 얹는 구조는 문서 대신 실측으로 확인한다 → [[bond-bridge-topology-verification]]

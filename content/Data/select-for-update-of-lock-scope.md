# 조인 있는 FOR UPDATE는 OF로 잠금 대상을 좁힌다

> **TL;DR**: 조인이 있는 `SELECT … FOR UPDATE`는 기본적으로 **결과 행에 참여한 모든 테이블의 행**을 잠근다. 사용자 행만 잠글 의도로 역할 테이블을 조인하면 역할 행까지 잠기고, 반대 방향의 두 트랜잭션이 서로의 역할 행을 기다리는 **데드락**이 된다. `FOR UPDATE OF <별칭>`으로 잠금 대상을 명시한다.

## 증상

- 서로 다른 두 행을 갱신하는 트랜잭션 둘이 동시에 돌면 한쪽이 deadlock 오류로 죽는다.
- 실측 사례: 사용자 A에게 역할 X→Y, 사용자 B에게 역할 Y→X를 동시에 배정하면 순환 대기 — 각자 자기 사용자 행과 함께 **조인된 역할 행**을 잠근 채 상대가 잡은 역할 행을 기다린다.

## 원인

PostgreSQL 문서의 정의: `FOR UPDATE`에 `OF` 절이 없으면 **쿼리에 쓰인 모든 테이블에서 반환 행에 기여한 행**이 잠긴다. 조인은 "읽기만" 이라는 직관과 달리, 락 절이 붙는 순간 조인 상대도 잠금 대상이 된다.

```sql
-- 의도: 사용자 행만 잠그고 현재 역할을 함께 읽기
SELECT u.id, u.status, r.role_key
FROM users u JOIN roles r ON r.id = u.role_id
WHERE u.id = $1
FOR UPDATE;          -- ← users 행 + roles 행이 함께 잠긴다
```

역할처럼 **공유되는 참조 행**(여러 사용자가 같은 역할을 가리킴)이 잠기면, 무관해 보이는 트랜잭션들이 그 행에서 충돌한다.

## 해결

```sql
FOR UPDATE OF u;     -- users 별칭 행만 잠근다. roles는 읽기만
```

- 잠글 필요가 있는 테이블(갱신 대상, 상태 판정 기준)만 `OF`에 올린다. 참조용 조인 상대는 뺀다.
- 존재·상태·이전 값·동일값 여부를 **잠근 한 번의 SELECT에서 함께 확정**하면, 잠금 획득과 판정 사이의 경합 창이 없어진다.
- 조인 상대의 값도 갱신 경합에서 보호해야 하면 `OF`에 추가하되, 그때는 **모든 트랜잭션이 같은 순서로 잠그는지**를 별도로 설계한다.

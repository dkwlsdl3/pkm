# 데이터 거버넌스

> **TL;DR**: 데이터의 품질·보안·권한·이력을 관리하는 정책·프로세스·책임 체계. 저장 레이어는 보통 **원천 보존 → 정제 → 활용** 3단으로 나눈다(Landing → Staging → Curated).

---

## 데이터 거버넌스란

조직 내 데이터의 **가용성, 무결성, 보안, 활용**을 보장하는 정책·프로세스·책임 체계.

핵심 목표:
- 데이터 품질 보장 (정확성, 완전성, 일관성)
- 접근 권한 통제 (누가 어떤 데이터를 볼 수 있는가)
- 데이터 이력 추적 (언제, 누가, 무엇을 변경했는가)

---

## 3단계 저장 레이어 (업계 일반 패턴)

```
[원천 시스템]
      │
      ▼
┌─────────────┐
│   Landing   │  원천 데이터(Raw) 최초 수집 및 백업
│             │  → 절대 수정하지 않음, 원본 보존
└─────┬───────┘
      │
      ▼
┌─────────────┐
│   Staging   │  데이터 정제, 표준화, 품질 검수
│             │  → 중복 제거, 형식 통일, 이상치 처리
└─────┬───────┘
      │
      ▼
┌─────────────┐
│  Curated    │  분석·비즈니스 활용을 위한 최종 가공 데이터
│  (Serving)  │  → 집계, 도메인 모델 적용, 리포트용
└─────────────┘
```

### 세 번째 레이어의 명칭

같은 개념을 부르는 이름이 여러 개다. 문서를 읽을 때 이름만 보고 다른 개념이라 오해하지 말 것.

| 명칭 | 쓰이는 맥락 |
|---|---|
| **Curated** / **Serving** | 일반적인 데이터 레이크·레이크하우스 문헌 |
| **Gold** (Bronze → Silver → Gold) | 메달리온 아키텍처(Databricks 계열) |
| **Mart** (Data Mart) | 전통적 DW 문헌 |

### Landing (원천 데이터)

- 외부 시스템에서 들어온 데이터를 **변환 없이** 그대로 저장
- 재처리 기준점 역할 — 파이프라인 오류 시 이 단계부터 재실행
- 보관 기간: 장기 (규정 준수 목적)

### Staging (정제 데이터)

- Landing 데이터를 비즈니스 규칙에 따라 정제
- 데이터 품질 검수 (null 처리, 타입 변환, 중복 제거)
- ETL/ELT 파이프라인의 중간 레이어

### Curated (분석 데이터)

- 최종 소비자(분석가, BI 도구, AI 모델)가 사용하는 레이어
- 집계 테이블, 도메인 엔티티, 피처 스토어 등
- 성능 최적화 (파티셔닝, 인덱싱, 컬럼 스토어)

## 기록 — 제거된 서술 (2026-07-31)

이 노트에는 세 번째 레이어를 **"Deepland"**라 부르고, 이 3단 모델을 **"사내 정책 체계"**라고 단정하는 서술이 있었다. 둘 다 **출처를 확인할 수 없어 제거했다.**

- "Deepland"는 업계 표준 용어가 아니고, 사내 문서·레포·설계자료 어디에도 근거가 없다. 정책을 정한 당사자도 그 명칭을 모른다
- 이 노트가 유일한 출처였고, 여기서 MOC와 사내 위키로 그대로 퍼졌다
- 이전 점검에서 *"Deepland (제품/코드명 의심)"*으로 플래그됐으나 확인되지 않은 채 방치됐다

**교훈**: 조직 고유 용어를 노트에 적을 때는 **어느 문서·누구에게서 온 것인지**를 함께 적어라. 출처 없는 고유명사는 시간이 지나면 검증이 불가능해지고, 지식 베이스가 유일한 출처가 되어 그 자리에서 사실처럼 굳는다. 플래그만 달고 넘기면 그대로 남는다. → [[unknown-is-not-absent]]

사내에서 실제로 쓰는 명칭이 확인되면 그때 근거와 함께 기록할 것.

# 데이터 거버넌스

> **TL;DR**: 데이터 품질·보안·권한을 관리하는 사내 정책 체계 — Landing → Staging → Deepland 3단계 흐름

---

## 데이터 거버넌스란

조직 내 데이터의 **가용성, 무결성, 보안, 활용**을 보장하는 정책·프로세스·책임 체계.

핵심 목표:
- 데이터 품질 보장 (정확성, 완전성, 일관성)
- 접근 권한 통제 (누가 어떤 데이터를 볼 수 있는가)
- 데이터 이력 추적 (언제, 누가, 무엇을 변경했는가)

---

## 3단계 데이터 모델

```
[원천 시스템]
      │
      ▼
┌─────────────┐
│   Landing   │  원천 데이터(Raw) 최초 수집 및 백업
│             │  → 절대 수정하지 않음, 원본 보존
└─────┬───────┘
      │
      ▼
┌─────────────┐
│   Staging   │  데이터 정제, 표준화, 품질 검수
│             │  → 중복 제거, 형식 통일, 이상치 처리
└─────┬───────┘
      │
      ▼
┌─────────────┐
│  Deepland   │  분석·비즈니스 활용을 위한 최종 가공 데이터
│             │  → 집계, 도메인 모델 적용, 리포트용
└─────────────┘
```

### Landing (원천 데이터)

- 외부 시스템에서 들어온 데이터를 **변환 없이** 그대로 저장
- 재처리 기준점 역할 — 파이프라인 오류 시 이 단계부터 재실행
- 보관 기간: 장기 (규정 준수 목적)

### Staging (정제 데이터)

- Landing 데이터를 비즈니스 규칙에 따라 정제
- 데이터 품질 검수 (null 처리, 타입 변환, 중복 제거)
- ETL/ELT 파이프라인의 중간 레이어

### Deepland (분석 데이터)

- 최종 소비자(분석가, BI 도구, AI 모델)가 사용하는 레이어
- 집계 테이블, 도메인 엔티티, 피처 스토어 등
- 성능 최적화 (파티셔닝, 인덱싱, 컬럼 스토어)

## ECM (Enterprise Content Management)

**문서 중앙화** — 개인 PC 저장 금지, 모든 기업 문서를 서버로 통합 관리.

| 항목 | 개인 PC 저장 (지양) | ECM 서버 (지향) |
|------|-------------------|----------------|
| 접근성 | 해당 PC에서만 | 어디서나 |
| 백업 | 개인 책임 | 자동 중앙 백업 |
| 권한 통제 | 불가 | ACL 기반 세밀한 통제 |
| 감사 추적 | 불가 | 접근·수정 이력 자동 기록 |
| 퇴사자 처리 | 데이터 유실 위험 | 즉시 권한 회수 |

솔루션 예: S소프트, 엑소소프트, SharePoint, Confluence

# lfs setstripe는 없는 경로에 빈 파일을 만들고 성공한다

> **TL;DR**: `lfs setstripe <path>`에 **존재하지 않는 경로**를 주면 그 이름으로 **빈 파일을 만들고 종료코드 0**으로 끝난다. 원래 "이 layout으로 새 파일을 만든다"는 용도가 있기 때문이다. 디렉터리에만 적용하려는 거라면 경로를 `<dir>/.`로 넘긴다. 그러면 없을 때 실패한다(종료코드 2).

## 증상

- 하위 폴더들을 순회하며 stripe를 거는 백그라운드 작업이 "성공"으로 끝났다.
- 그런데 작업 도중 사용자가 지운 폴더 자리에 **root 소유 0바이트 파일**이 같은 이름으로 생겨 있다.
- 사용자에게는 "지운 폴더가 파일로 되살아난" 것으로 보이고, 같은 이름으로 폴더를 다시 만들 수도 없다.

## 원인

- `lfs setstripe`는 디렉터리의 기본 layout 설정과 **지정 layout으로 새 파일 생성**을 겸한다. 경로가 없으면 후자로 동작한다.
- 목록을 먼저 뽑고 나중에 적용하는 순회는 그 사이 경로가 사라지는 경합(TOCTOU, Time-Of-Check to Time-Of-Use — 확인한 시점과 쓰는 시점 사이에 상태가 바뀌는 문제)을 피할 수 없다. 사전 `[ -d ]` 검사로는 막히지 않는다.
- 작업을 root로 돌리므로 생긴 파일도 root 소유다.

## 해결

```bash
# 디렉터리에만 적용 — 없으면 실패(종료코드 2), 파일을 만들지 않는다
lfs setstripe -c 4 "/mnt/lustre/nas/shared/sub/."

# 순회 시: 사라진 경로(종료코드 2)는 "건너뜀"으로 집계, 그 밖의 실패는 작업 실패로
```

- 경로 끝의 `/.`는 "이 경로는 디렉터리여야 한다"를 커널 경로 해석에 맡기는 관용구다. 별도 검사 없이 경합까지 막는다.
- 사라진 경로를 실패가 아니라 **건너뜀**으로 따로 세면, 작업 결과가 거짓 성공도 거짓 실패도 아니게 된다.
- 2026-10 Lustre 2.15.8에서 실측했다. 리뷰 단계에서 잡혔다.

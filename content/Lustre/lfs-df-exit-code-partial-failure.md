# lfs df 비영 종료코드는 개별 타깃 실패의 합

> **TL;DR**: `lfs df`는 비활성 OST(Object Storage Target, 실제 데이터가 저장되는 Lustre 저장 단위)가 **하나만 있어도 비영 종료코드(예: 22)** 로 끝난다. 표는 정상 출력되고 stderr는 비어 있다. 종료코드만 보고 "명령 실패"로 판정하면 멀쩡한 용량 데이터를 통째로 버리게 된다.

## 증상

- 용량을 `lfs df` 파싱으로 얻는 모니터링·화면이 **전부 "수집 실패" 상태**가 된다. 표시값이 캐시된 옛 값(실측 사례: 캐시 10.5 MiB vs 실제 약 44.5 GiB)에 얼어붙는다.
- 수동으로 `lfs df`를 치면 표가 멀쩡히 나와서 원인을 못 찾는다. `echo $?` 를 쳐야 비로소 비영 종료코드가 보인다.
- 파일시스템에서 OST 하나를 비활성화(deactivate)한 뒤부터 시작된다.

## 원인

- `lfs df`의 종료코드는 **명령 전체의 성패가 아니라 개별 타깃 조회 실패의 합**이다. 비활성 OST는 조회가 안 되므로 그 타깃 몫의 오류 코드가 종료코드로 올라온다.
- 나머지 타깃의 표·요약 행은 정상 출력된다. 즉 "부분 실패 + 유효한 부분 결과"인데, 종료코드만 보는 호출자는 이것을 "전체 실패 + 결과 없음"으로 오판한다.

## 해결

종료코드를 성패 판정에 단독으로 쓰지 않는다. 판정 순서:

1. **비활성 타깃 목록을 먼저 읽는다** — 어떤 타깃이 빠질지 사전에 안다.
2. 표를 **엄격히 파싱**하고, 행 합계와 요약 행을 **교차 대조**한다.
3. 조회 전후로 타깃 구성이 바뀌었으면 전체를 재시도한다.
4. 위가 전부 성립할 때만 비영 종료코드를 수용하고 결과를 신뢰한다.

추가 방어:

- **값의 신뢰도를 타입으로 운반한다** — 숫자를 「완전 판정」 안에만 두면, 실패를 0으로 받아 계산에 넣는 실수가 타입 수준에서 막힌다.
- 할당이 막힌 상태 문자가 붙은 타깃은 가용량에서 빼고 별도 목록으로 알린다(값을 작게 만드는 방향이라 여전히 안전). **모르는 상태 문자를 만나면 계산하지 않는다.**
- 수집 실패한 회차에는 **수집 시각을 갱신하지 않는다.** 값은 옛것인데 시각만 새것이면 데이터가 얼마나 낡았는지 알 방법이 사라진다.

```bash
lfs df; echo "exit=$?"   # 비활성 OST가 있으면 표는 정상 + exit=22
lctl dl                  # 타깃 활성/비활성 상태 확인
```

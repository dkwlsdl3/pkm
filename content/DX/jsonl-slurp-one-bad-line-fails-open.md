# JSONL을 jq -s로 통째로 읽으면 깨진 한 줄에 게이트가 열린다

> **TL;DR**: JSONL(JSON Lines, 한 줄에 JSON 하나씩 쓰는 로그 형식)을 `jq -s`(slurp, 전체를 배열 하나로 읽기)로 읽으면 **깨진 줄 하나에 파일 전체 파싱이 실패**한다. 그 실패를 "판정 불가 → 통과"로 처리하는 게이트는 그 파일에 대해 **영구히 열린다**(fail-open). 줄 단위로 읽어 깨진 줄만 건너뛰고, 판정 없이 통과시킨 건은 반드시 기록을 남긴다.

## 증상

- 에이전트 세션 로그를 읽어 습관 위반을 판정하는 Stop 훅(habit-gate)의 기록에 `slice-fail`이 196건 있었다.
- 해당 세션 10개는 깨진 줄이 생긴 시점 이후 **모든 턴이 판정 없이 통과**했다.
- 훅 자체는 오류 없이 종료하므로 겉으로는 정상 동작처럼 보인다.

## 원인

- `jq -s`는 입력 전체를 하나의 배열로 만든다. 줄 하나라도 JSON이 아니면 전체가 오류다.
- 세션 로그는 계속 덧붙여지는 파일이라, 쓰는 도중 잘린 줄 같은 **깨진 줄이 섞일 수 있다.**
- 훅은 파싱 실패를 "이번 턴은 판정할 수 없음 → 막지 않음"으로 처리했다. 그 줄이 파일에 남아 있는 한 이후 모든 턴이 같은 이유로 통과한다.

## 해결

```bash
# 줄 단위로 읽고, 파싱 안 되는 줄만 버린다
jq -cR 'fromjson?' session.jsonl | jq -s '...'

# 버린 줄 수를 따로 센다 — 0이 아니면 기록
bad=$(jq -R 'fromjson? // "BAD"' -c session.jsonl | grep -c '^"BAD"$')
```

- `-R`(raw input)로 줄을 문자열로 받고, `fromjson?`의 `?`로 실패한 줄을 조용히 빼낸다.
- 판정 없이 통과시키는 경우에는 **세션 ID와 사유를 남긴다.** 통과 자체보다 "몇 번 판정을 못 했는지 모른다"는 상태가 더 위험하다.

> [!NOTE]
> 일반화: 입력 일부가 깨졌다고 판정 전체를 포기하면 게이트는 그 입력에 대해 꺼진다. 깨진 부분만 격리하고 나머지로 판정한다.

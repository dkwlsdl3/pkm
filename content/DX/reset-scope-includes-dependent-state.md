# 초기화 범위는 지운 자원을 가리키는 설정·계정·상태 파일까지다

> **TL;DR**: 제품 초기화(purge·reset)에서 "데이터를 지운다"의 범위는 데이터만이 아니다. 그 데이터를 **가리키던 설정, 계정, DB 밖의 상태 파일**까지 한 묶음이다. 하나라도 남으면 재설치가 그 잔재를 "이미 있음"으로 읽어 건너뛰고, 유령 계정이나 관리자 0명 상태를 만든다.

## 개요

- **무엇**: 저장소·DB를 지우면, 그것을 전제로 하던 다른 기록이 **허공을 가리키는 참조**가 된다.
- **왜 / 언제**: 설치 도구에 purge·reset을 만들거나 고칠 때, 시험 장비를 반복 재설치할 때 해당한다.

## 동작 / 예시

업계 초기화 기능을 비교해 뽑은 공통 규칙은 셋이다.

| 제품 | 동작 |
|---|---|
| TrueNAS | 풀 삭제 시 그 풀을 쓰던 공유·작업 설정도 함께 정리, 설정 초기화는 별도 메뉴 |
| QNAP 고급 초기화 | 볼륨·사용자·공유를 한 번에 초기화 |
| Synology Mode 2 | 시스템 재설치 시 설정·사용자까지 초기화 |
| `cephadm rm-cluster` | 데몬·데이터·설정·키링을 지우고 남는 것을 알림 |
| `kubeadm reset` | 지우지 않는 것(CNI 설정, iptables 등)을 출력해 수동 정리를 안내 |

1. **저장소를 지우면 그 저장소를 가리키던 설정도 지운다** (공유 폴더 정의, 백업 작업, 마운트 설정)
2. **사용자·그룹·공유는 한 묶음으로 지운다** (앱 DB 계정만 지우고 OS·Samba 계정을 남기면 유령 계정)
3. **남기는 것은 화면·문서에 적고 손으로 지울 방법을 준다** (`kubeadm reset`처럼)

실제로 겪은 잔재 사례:

```text
purge: DB 재생성 (정상 종료)
init : /var/lib/<app>-initial-admin.json 존재 → "관리자 이미 있음" → 생성 건너뜀
결과 : DB 사용자 0명, 로그인 불가. 기록 파일을 치워도 관리자 준비를 다시 하지 않아 복구 경로 없음
```

점검 방법: **"DB 밖에서 DB 안을 가리키는 상태"** 를 코드에서 전수 조사한다. 한 번에 5종이 나왔다(초기 관리자 기록, 홈 복구 기록, 백업 설정, 프로필 사진, 외부 연동 이력).

## 주의

> [!WARNING]
> - "purge가 종료코드 0으로 끝났다"는 범위가 맞다는 증거가 아니다. **purge 직후 init이 처음 설치처럼 동작하는지**를 시험으로 확인한다.
> - 지우지 못한 것이 있으면 0이 아니라 실패로 끝내고 무엇이 남았는지 출력한다.

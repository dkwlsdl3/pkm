# 파괴적 설치 앞에는 아무것도 바꾸지 않는 사전점검을 둔다

> **TL;DR**: 설치 도구가 1단계에서 곧바로 패키지 설치를 때리면, 망이 막힌 현장에서는 **절반 깔다 멈춘 장비**가 남고 `reset` 은 그것을 되돌려 주지 않는다. 파괴적 작업이 하나라도 돌기 전에 장비와 망의 가부를 말하는 **읽기 전용 점검**을 두고, 실제 설치가 쓰는 주소·토큰을 **같은 정본**에서 읽게 해라.

## 개요

- **무엇**: 설치·배포처럼 되돌리기 어려운 절차 앞에 붙이는 읽기 전용 검사 단계(pre-flight).
- **왜 / 언제**: 도구를 돌리는 사람이 그 제품을 잘 모를 수 있고, 현장 환경(망 차단, 프록시, 토큰 만료)을 사전에 알 수 없을 때.

## 동작 / 예시

판정은 세 단계로 나눈다.

| 판정 | 뜻 | 설치 진행 |
|---|---|---|
| `Pass` | 문제 없음 | 진행 |
| `Warn` | 설치는 되지만 그대로 두면 나중에 문제 | 진행 |
| `Fail` | 지금 상태로는 안 된다 | **중단** |

각 검사 결과에는 **판정만 적지 말고 무엇을 봤는지(실측값)** 와 **실패했을 때 무엇을 하면 되는지(조치)** 를 함께 담는다. 모르는 사람이 혼자 돌리는 것이 전제이므로 `Fail`·`Warn` 에 조치가 없으면 현장에서 막다른 길이 된다 — 생성자가 그것을 강제하게 만들어라.

```rust
/// `Fail` 이 하나도 없어야 설치를 시작한다. `Warn` 은 막지 않는다.
pub fn ok_to_install(&self) -> bool {
    !self.reports.iter().any(|r| r.verdict == Verdict::Fail)
}
```

**망 차단과 인증 실패는 다른 사고다.** `401` 은 망이 뚫렸는데 토큰이 없는 것이고, 연결 거부·DNS 실패는 망 자체다. 현장에서 이 둘을 구분하지 못하면 엉뚱한 곳을 몇 시간 고친다 — `curl` 종료 코드를 사람 말로 옮겨 보여준다.

## 주의

> [!WARNING]
> **점검이 보는 주소와 설치가 실제로 받는 주소가 갈리면 점검이 거짓말을 한다** — 전부 초록인데 설치가 못 받는 상황이 된다. "설치가 인터넷에서 무엇을 끌어오는가"의 정본을 한 자리에 두고, 점검과 설치가 **같은 정본을 읽는지 시험으로 잠가라.**

> [!NOTE]
> 사전점검 명령 자체는 **시스템을 하나도 바꾸지 않아야** 한다. 그래야 현장에서 몇 번이고 다시 돌릴 수 있다. 인자를 받지 않는 명령 목록에 넣을 때는 "파괴적이라서"가 아니라 "인자를 받지 않아서"가 기준임을 분명히 해라 — 목록의 뜻이 흐려지면 나중에 잘못된 명령이 섞인다.

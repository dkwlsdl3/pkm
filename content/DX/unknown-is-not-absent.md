# "모름"을 "없음·정상"으로 접지 말라

> **TL;DR**: 조회·확인이 **실패했다**는 사실을 "없다 / 정상이다 / 최신이다"로 접으면 화면과 로그가 **거짓 안심**을 준다. 불리언 하나로는 "없다"와 "못 물어봤다"를 구분할 수 없다. **세 번째 상태(확인 불가)를 명시적으로 만들고**, 값이 없으면 확인 불가 쪽으로 기울여라.

---

## 왜 문제인가

같은 결함이 계층마다 반복해서 나타난다. 공통 뿌리는 하나다 — **실패를 성공처럼 표현한 것.**

| 사례 | 잘못된 처리 | 결과 |
|---|---|---|
| 패키지 업데이트 확인 | 외부 명령 종료 코드 중 "없음(0)·있음(100)" 외 전부를 "없음"으로 | 저장소 미등록·명령 부재·권한 거부가 모두 **"최신 상태"**로 표시 |
| 프론트 조회 실패 | `console.error`로 삼키고 목록을 빈 배열, 버전을 'unknown' | 화면이 "설치 0개 · 업데이트 0개(초록) · 최신 상태"를 **단정** |
| 프로세스 종료 스크립트 | 종료를 검증하지 않고 "전체 종료 완료" 출력 | 실제로는 살아 있어 다음 기동이 실패하고, **원인 추적이 늦어진다** |
| 권한 데이터 조회 실패 | `permissions=None`을 "권한 없음"과 동일 취급 | 운영자가 "권한 부족"과 "권한 데이터 장애"를 구별할 수 없다 |
| 목록에 상세 없음 | 상세 컬럼을 전부 `N/A`로 표시 | **"값이 비었다"와 "보고가 아직 없다"**를 구분 불가 |
| 관찰·shadow 로그 | "경고 0건"을 곧 안전으로 해석 | 관찰 지점이 닿지 않는 범위는 **미관찰인데 무경고로 보인다** |
| 자료 조사 | "검색해서 안 나왔다"를 "존재하지 않는다"로 판정 | 진행 중인 사건은 **날짜별로 수치가 갱신**되는데, 초기 보도만 보고 후속 수치를 "출처 없음"이라 단정 |
| 기능 활성 여부 조회 | `.ok().flatten()` 으로 **조회 실패와 "설정 행 없음"을 뭉개고** 환경변수 기본값으로 폴백 | 환경변수를 켜둔 배포에서는 관리자가 DB에서 끈 뒤에도 조회가 한 번 삐끗하면 **"켜짐"으로 읽혀 그대로 진행**된다(fail-open). "env 폴백이니 fail-closed"라는 주석 자체가 틀렸다 |
| 서비스 활성 판정 | `systemctl is-active <없는 유닛>` 이 돌려주는 `inactive` 를 "꺼짐"으로 해석 | **"유닛 없음"과 "꺼짐"이 구분되지 않아** 화면이 "돌고 있는데 비활성"이라 거짓을 말한다 → [[systemd-unit-name-distro-variance]] |

### 조사·검증에도 같은 함정이 있다

사실 검증을 하다 보면 이 실패를 **반대 방향으로** 겪는다. 원문에 없는 내용을 걸러내는 데 집중하다가, **아직 못 찾은 것**까지 "없다"고 판정하는 것이다.

- 진행 중인 사건은 보도가 갱신된다 ⇒ **"틀렸다"가 아니라 "언제 시점의 숫자인가"**를 먼저 물어라
- 1차 검색으로 안 잡히면 **검색 범위·시점을 바꿔 재확인**한다. 없다고 결론내기 전에
- 수치를 인용할 때는 **출처와 시점을 함께** 적는다(초기값과 확정값이 다를 수 있다)
- 실제 사례: [[openai-huggingface-sandbox-escape-2026-07]] 조사 중 후속 보도를 못 찾아 실재하는 수치를 "허구"로 오판했다

## 해결

### 1. 불리언을 3값으로 승격한다 (기존 필드는 남긴다)

```rust
// 기존 필드를 지우지 않고 추가해 호환을 지킨다
struct UpdateCheck {
    updates_available: bool,        // 기존 소비자용
    outcome: CheckOutcome,          // upToDate | updatesAvailable | checkUnavailable
}
```

- 종료 코드 해석을 **순수 함수로 분리**해 테스트한다(`classify_check_exit`)
- 알려진 코드 외에는 전부 `checkUnavailable`
- **파싱 실패도 확인 불가**로 — "있음"을 받았는데 0건을 뽑았다면 그건 파싱 실패이므로 "최신"이라 단정하면 **있는 업데이트를 없다고 말하게 된다**

### 2. 값이 없으면 "확인 불가"로 기울인다

```js
// outcome이 없으면(요청 실패 또는 구버전 백엔드) 확인 불가로 처리
const status = softwareUpdateStatus(res)   // 판정도 순수 함수로 분리
```

신 프론트 + 구 백엔드 과도 구간에서는 정상인데도 '확인 불가'로 보일 수 있다. 그래도 **반대 방향 오표시보다 안전하다** — 모르는 것을 "최신"이라 말하지 않는 쪽을 고른다.

### 3. 화면에 확인 불가를 표시한다

지표를 '확인 불가'로 + 경고 문구 + **다시 확인 버튼**. 초록 배지와 "모든 항목이 최신입니다"를 지운다.

### 4. 거부·실패 사유를 로그·메시지에서 분리한다

```
MatrixDeny         warn   "권한 부족: category=X requires read|full"
PermissionsUnknown error  "권한 데이터를 조회할 수 없음: category=X"
MetadataMissing    error  "라우트 메타데이터 없음"
```

전부 fail-closed로 거부하되 **운영자가 원인을 구별할 수 있게** 한다. "모름 ≠ 없음"은 판정 단계에서도 유지한다.

### 5. 근거가 없는 구분은 만들지 않는다

반대 방향의 절제도 필요하다. '수집중'과 '미수집'을 나누려면 등록 시각·마지막 시도 시각이 있어야 하는데 응답에 없다면 **나누지 않는다.** 없는 정보를 만들어 표시하는 것도 거짓 신호다.

### 6. 판정 근거로 쓸 컬럼을 확인한다

"상세 미수집"을 판정할 때 **상세 테이블 소속 컬럼만** 써야 한다. 다른 테이블에서 오는 컬럼(항상 채워짐)을 판정에 넣으면 모든 항목이 "수집됨"이 되어 배지가 영원히 안 뜬다. 그리고 `false`·`0`처럼 **falsy지만 유효한 값**이 있으므로 falsy 검사가 아니라 **null/undefined 검사**여야 한다.

# 여러 에이전트 세션이 한 워크트리를 공유할 때

> **TL;DR**: 경로 지정 커밋(`git commit -- FILE`)은 **공유 파일을 막지 못한다** — 그 파일의 현재 상태를 통째로 담기 때문이다. 경로 없는 `git stash`·`clean`·`reset --hard`는 옆 세션의 미커밋 작업을 걷어간다. 공유 문서는 **커밋 주체를 한 세션으로 고정**하고, 세션 규칙은 주기적으로 비워지는 커서 문서가 아니라 **영구 문서**에 둔다.

## 증상

에이전트 세션 3~4개를 한 저장소(같은 워크트리)에서 병렬로 돌릴 때 나타난다.

- 각 세션이 "내 파일만 커밋했다"고 보고하는데, 커밋에 **다른 세션의 미완성 변경이 섞여** 있다
- 옆 세션이 커밋 직전에 트리가 되돌아가 **되돌려진 상태가 커밋된다**
- 공유 문서(할 일 목록·작업 커서)가 세 세션의 장문으로 넘쳐 커서 구실을 못 한다
- 세션이 끝나면 아무도 공유 문서를 커밋하지 못하는 상태가 된다

## 원인

### 1. pathspec 커밋은 스테이징이 아니라 스냅샷이다

```bash
git commit -- TODO.md      # "내 줄만 담긴다"고 오해하기 쉽다
```

실제로는 **그 시점 워킹트리의 `TODO.md` 전체**가 커밋된다. 옆 세션이 방금 추가한 줄까지 포함된다. 라인 단위로 고르려면 `git add -p`가 필요하지만 **대화형이라 에이전트가 쓸 수 없다.**

⇒ 파일 단위로 소유권을 나눌 수는 있어도, **한 파일을 여러 세션이 동시에 수정하는 구조는 커밋으로 분리할 수 없다.**

### 2. 트리 전체를 되돌리는 명령

```bash
git stash            # 경로 없으면 기본값이 트리 전체
git checkout -- .
git restore .
git clean -fd
git reset --hard
```

`git stash`는 "내 변경만 잠깐 치운다"는 의도로 쓰기 쉽지만 **경로가 없으면 트리 전체**를 걷어간다. 옆 세션의 미커밋 작업이 함께 사라지고, 그 순간 옆 세션이 커밋하면 **되돌려진 상태가 영구 기록된다.**

빌드 경고 수를 변경 전후로 비교하려다 이 사고가 실제로 났다(손실은 없었다). 용건 자체는 정당하다 — 방법만 바꾸면 된다.

### 3. 규칙을 커서 문서에 두면 함께 지워진다

작업 커서 문서는 "끝난 항목은 지운다"가 원칙이다. 거기에 세션 운영 규칙 절이 자라면, **커서를 정리할 때 규칙이 같이 지워진다.** 규칙이 특정 세션 이름("통합관리세션")에 의존하고 그 이름을 설명하는 곳이 커서 문서의 지워지는 한 줄뿐이라면, 그 세션이 끝나는 순간 **아무도 권한을 갖지 못하는 상태**가 된다.

## 해결

**공유 파일 — 커밋 주체를 하나로 고정한다.**

- 공유 문서(할 일·커서)는 **어느 세션도 스스로 커밋하지 않는다.** 사용자가 지시한 세션만, 지시받은 그때 커밋한다.
- 지시받은 세션이 없으면 **미커밋이 정상 상태**다. `git status`에 남아 있는 것을 이상 신호로 읽지 않는다.
- 규칙은 **세션 이름이 아니라 역할**로 쓴다("사용자가 지시한 세션"). 이름에 매달면 그 세션 종료와 함께 규칙이 죽는다.

**트리 조작 — 자기 경로로 좁힌다.**

```bash
# 금지: 트리 전체를 되돌리는 명령 (경로 없는 stash/checkout/restore/clean/reset --hard)
# 허용: 자기 소유 경로만 지정
git stash push -- service/backend/src/api/auth/
# ... 측정 ...
git stash pop
```

측정 목적이면 **측정 직후 즉시 되돌린다.** 좁힌 stash도 살아 있는 동안은 위험 구간이다.

**규칙 문서의 위치.**

- 세션 운영 규칙 → `AGENTS.md` 등 **영구 문서**
- 지금 하는 일 1건 + 다음 작업 커서 → **커서 문서** (그 이상은 쓰지 않는다)
- 앞으로 할 일 → **할 일 목록 문서**
- 커서 문서에 크기 상한(예: 8KB)을 두면 장문 유입을 기계로 막을 수 있다

**세션 간 전달.**

에이전트는 **세션 시작 시점의 규칙 문서 스냅샷**을 컨텍스트에 갖고 있다. 규칙을 방금 바꿨다면 전달 프롬프트에 그 사실을 명시해야 한다 — "당신 컨텍스트의 `AGENTS.md`는 낡았다. 지금 `## 병렬 세션` 절을 다시 읽어라."

> [!WARNING]
> 파일 소유권 표를 만들어도 **공유 파일 하나가 남으면 커밋은 오염된다.** 소유권 분리는 "각자 다른 파일"까지만 유효하다.

> [!NOTE]
> 진짜 격리가 필요하면 워크트리를 분리한다(`git worktree add`). 다만 실화면 검증이 필요한 프로젝트는 개발 서버 포트·DB까지 갈라야 하므로 비용이 있다. 문서·규칙 기반 조율은 그 비용을 피하는 대신 위 함정을 안고 가는 선택이다.

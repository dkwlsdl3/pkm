# 코드 전수조사 수집기 설계 — 수집기 자신이 먼저 조사 대상이다

> **TL;DR**: "실패를 조용히 삼키는 자리" 처럼 결함 **모양**을 코드베이스 전체에서 세는 스크립트를 만들 때 지킬 것 넷. ① **수집기 자신이 그 결함을 갖지 않게** — 의존 명령이 없으면 0 건이 아니라 중단(fail-closed) ② **적중 수는 검토 단위가 아니다** — 고유 `파일:행` 으로 dedupe 하고 인과 사슬로 다시 묶는다 ③ **성격이 다른 그룹은 합계에 섞지 않는다**(반대 성격·반대 방향·대조군은 소계) ④ **정답지로 재현율을 잰다** — 이미 아는 결함 N 건 중 몇 건을 잡는지.

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| 관용구 | idiom | `unwrap_or(default)`, `.ok()`, `catch {}` 처럼 결함이 자주 숨는 코드 모양. 수집기의 정규식 하나가 관용구 하나다 |
| fail-closed | — | 판정 근거를 못 얻으면 성공이 아니라 실패로 끝내는 것. 여기서는 "도구가 없으면 0 건이 아니라 오류" |
| 정답지 | ground truth | 이미 확인된 실결함 목록. 수집기가 이것을 잡는지로 규칙의 재현율을 측정한다 |
| 대조군 | control group | 이미 옳게 처리된 자리. 결함 후보가 아니라 "옳은 형태의 예" 로 쓴다 |

## 개요

- **무엇**: `rg` 패턴 수십 개를 그룹으로 묶어 전수 실행하고 `파일:행:규칙` 을 뱉는 감사 스크립트와 그 결과를 판정하는 방법.
- **왜 / 언제**: 같은 모양의 결함이 하나 발견되면(예: 조회 실패를 기본값으로 접는 자리) 나머지가 어디 있는지 사람이 훑을 수 없을 때. 하루에 8,330 고유 위치를 냈다.

## 동작 / 예시

```bash
#!/usr/bin/env bash
set -euo pipefail

# ① 수집기 자신의 fail-closed — 의존 명령 부재를 0 건으로 보고하지 않는다
for cmd in rg awk; do
  command -v "$cmd" >/dev/null || { echo "FATAL: 필수 명령 '$cmd' 가 없다. 개수를 0 으로 보고하지 않고 중단한다" >&2; exit 4; }
done

# --manifest : 실제로 본 범위를 함께 찍는다 (파일 수·확장자·제외 디렉터리). "0 건" 의 근거다
# --unique   : 파일:행 기준 dedupe. 한 행이 규칙 여러 개에 잡힌다(실측 10,045 행 → 8,330 고유)

# ③ 그룹은 성격별 소계 — 합계 하나로 내지 않는다
#   주 조사 R(값으로 접음)·J(JS catch 삼킴)·Q(SQL)·A(CI·셸)   → 결함 후보
#   참고    P(패닉 = 조용함의 반대)·V(성공을 실패로 = 반대 방향) → 별도 소계
#   대조군  C(이미 옳게 처리한 자리)                           → 결함 후보가 아니다
```

**정답지 재현율**: 과거에 확인·수정한 결함 8 건을 골라 수집기가 몇 건을 잡는지 본다. 첫 판은 2/8 이었다 — 대괄호 인덱싱 `[N]` 만 보고 함수 호출형 `row.get(N)` 을 못 잡았다. 규칙을 보완해 4/8. **재현율 0 인 유형은 규칙이 없는 것**이므로 그 유형을 새 규칙으로 넣는다.

**판정 순서**: 표시(UI) 자리가 아니라 **실패의 의미를 바꾸는 공통 경계**부터 — HTTP 응답 계약, 상태 매퍼, 태스크 감독, 프로세스 종료코드 → 부분 성공·원자성 경계 → 그 경계를 타는 개별 행위(파괴·인증·정합·표시). 공통 경계 하나가 하류 수십 곳을 "조용하게" 만든다.

**판정 어휘**: `결함(사슬 근거)` / `정당한 삼킴(사유)` / `기지(문서·커밋 지목)` / `확인 불가(사유)`. 후보 하나에 이 넷 중 하나를 붙인다 — "확인 불가" 를 "결함 아님" 으로 접지 않는다.

## 주의

> [!WARNING]
> **수집기가 조사 대상 결함을 갖고 있었다.** `rg` 를 지운 PATH 에서 돌리자 개수 칸을 비운 채 종료코드 0 으로 끝났다 — "0 건 매칭인데 성공 종료" 를 찾는 스크립트가 자기 안에 그것을 갖고 있었다. 적대검증이 잡았고, 고친 뒤 같은 조건에서 종료코드 4 로 **역검증**했다. 전수조사 도구는 만든 직후 **도구를 빼앗아 돌려보라.**

> [!WARNING]
> 착수 보고에 "후보 9,469 건" 처럼 **적중 수를 조사량으로 쓰지 말라.** 규칙 중복(한 행이 최대 4 규칙)과 반대 성격 그룹이 섞인 숫자다. 고유 위치·성격별 소계로 정정해야 한다.

전제도 실측으로 정정한다 — "프론트는 TS/Vue" 라는 배정문과 달리 `.js` 124 · `.vue` 123 · `.ts` 7 이었다. 패턴이 `.ts` 만 보면 절반을 놓친다.

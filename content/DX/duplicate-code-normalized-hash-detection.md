# 이름이 다른 복사본은 토큰 복붙 탐지로 못 잡는다

> **TL;DR**: jscpd 류의 클론 탐지는 **토큰이 연속으로 같은 구간**을 찾는다. 변수명만 바꾼 복사본은 자주 놓친다. 함수 본문에서 **식별자·문자열·숫자를 지우고 해시**하면 "이름이 달라도 하는 일이 같은" 것이 묶인다. 그리고 클론은 **쌍이 아니라 무리로 세야** 판정 가능한 숫자가 된다(26벌 = 325쌍).

## 개요

- **무엇**: 중복 코드 조사를 두 축으로 돌리는 방법 — ①토큰 기반 클론 탐지(연속 복붙) ②정규화 해시(구조 동일).
- **왜 / 언제**: "이런 게 또 있는가"를 답해야 할 때. **복사본은 결함을 복제하는 것이 아니라 "수정을 못 받는
  자리"를 만들기 때문에**, 결함 하나를 고친 뒤 반드시 한 번 돌려야 한다.

## 동작 / 예시

**축 1 — 정규화 해시.** 함수 본문에서 이름·리터럴을 지우고 남은 구조를 해시한다.

```js
// scan-functions.mjs (개념)
function fingerprint(body) {
  return sha1(body
    .replace(/\/\/.*$|\/\*[\s\S]*?\*\//gm, '')   // 주석
    .replace(/(['"`])(?:\\.|(?!\1).)*\1/g, 'S')  // 문자열 리터럴
    .replace(/\b\d+(\.\d+)?\b/g, 'N')            // 숫자
    .replace(/\b[A-Za-z_$][\w$]*\b/g, 'I')       // 식별자
    .replace(/\s+/g, ''));                       // 공백
}
// 같은 지문 → 이름만 다른 복사본
```

**축 2 — 클론을 무리로 정리.** jscpd 는 "쌍"을 준다. 26벌짜리 복사본은 **쌍으로 세면 325개**가 되고,
큰 클론 안에 작은 클론이 또 잡혀 숫자가 부풀려진다.

- 파일별로 구간을 병합한다(포함되는 구간은 흡수하되 **넓히지 않는다** — 넓히면 무관한 코드가 딸려 온다)
- 겹치는 구간을 간선으로 보고 **연결요소**를 구한다 → 무리
- 테스트·템플릿·임포트 뭉치는 별도 통으로 분리한다(잡음)

```bash
# 실행 인자에 반드시 넣을 것
npx jscpd src/ \
  --max-lines 100000 --max-size 10mb \   # ★기본 상한에 큰 파일이 경고 없이 빠진다
  --format "javascript,typescript,vue,rust,sql" \
  --reporters json --output ./.jscpd
```

**읽는 법**: 중복 라인 비율의 **총량은 대개 정상 범위**다(5% 안팎). 판단해야 할 것은 **몰린 곳**이다 —
포크 복사된 크레이트 쌍, 종단점마다 손으로 붙인 검사 앞머리, 화면마다 복사된 표시 함수.

## 주의

> [!WARNING]
> **1차 측정을 그대로 믿지 마라.** 흔한 누락 셋: ①기본 크기·줄 수 상한에 큰 파일이 **경고 없이** 빠진다
> ②SQL·설정 파일이 스캔 대상에 안 들어간다 ③스크립트 자체의 버그. 재현 명령을 문서에 통째로 적어 두고
> 무엇을 켜야 하는지 이유와 함께 남겨라.

> [!WARNING]
> **도구 한계를 함께 기록하라.** 예: `.vue` SFC 는 보고된 줄 번호가 실제와 어긋나는 경우가 많다(측정 135개
> 중 117개 불일치). 그 언어의 무리 판정은 신뢰하지 말라고 문서에 적어야, 다음 사람이 그 숫자로 결정하지 않는다.

> [!NOTE]
> 조사 도구를 **자동 실행 경로(CI·pre-commit)에 연결하지 마라.** 이 조사는 판단이 필요한 작업이고,
> 임계값으로 게이트를 걸면 잡음에 사람이 둔감해진다. 직접 실행할 때만 돌게 두고 결과 문서를 정본으로 남긴다.

> [!NOTE]
> 두 크레이트/패키지 사이의 복사는 **공용 모듈로 걷을 수 없는 경우가 있다**(워크스페이스 미구성 등).
> 그때는 "지금은 양쪽에 같은 모듈을 둔다"를 결정으로 적고, **크레이트 안에서만이라도 유일한 출처**를 만든다.

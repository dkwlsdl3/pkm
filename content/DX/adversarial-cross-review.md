# 적대적 교차검증 — 구현자≠검증자

> "이 코드가 틀렸다고 가정하고 반박하라"를 **다른 에이전트/사람**에게 시키면, 자기 검토로는 절대 안 잡히는 결함이 나온다.

## 실측 결과 (하루 2회전)
- 1회전(타인 작업 8건 검증): 존재하지 않는 UI 컴포넌트 variant 전달(런타임 스타일 누락), API 계약상 알 수 없는 값으로 만든 지표 산식, 실패 상태를 정상처럼 표시, 조회 fan-out 순차 await 타임아웃 누적 등 — **8건 전부 실질 결함**.
- 2회전(자기 구현을 사후 검증): 워크플로를 어기고 직접 구현한 코드에서 **버그 3개** 적발. 혼자 만들면 혼자의 맹점이 그대로 나간다는 게 수치로 증명됨.

## 잘 되게 하는 조건
1. **반박 미션으로 명시**: "검토해줘"(호의적)가 아니라 "틀렸다고 가정하고 반박하라, 불확실하면 refuted 쪽으로".
2. **계약은 원문 대조 지시**: "응답 필드는 X 파일 사용부에서 확인하라" — 검증자가 스스로 원문을 읽게.
3. **공격면 목록 제공**: 제거 여파(참조 잔재), 죽은 코드, 타입/필드 계약, 실패 상태 표현, 문법(도구로 치환한 코드).
4. **검증자와 구현자 분리**가 핵심 — 같은 주체의 셀프 리뷰는 같은 가정을 통과시킨다.
5. 검증 후엔 지적을 맹신하지 말고 **각 지적의 타당성을 재판정**(기존에 있던 경고인지, 의도된 트레이드오프인지).

## 라운드는 한 번으로 끝나지 않는다

휴지통 삭제 결함 하나를 5라운드 돌렸는데, **매 라운드에서 앞 라운드가 "막았다"고 한 것이 실제로는 열려
있었다.** 반복된 실패 형태 셋:

1. **가드를 무력화하는 경로가 코드 안에 이미 있다** — "부모 디렉터리가 보이면 신뢰한다"로 고쳤는데, 다른
   창구가 조건 없이 그 디렉터리를 만들고 있었다. 가드를 넣었으면 **그 가드의 전제를 깨는 호출자를 전수로 찾아라.**
2. **처방이 마지막 한 걸음에서 끊긴다** — 압축 해제 *전에만* 조인 권한을 tar 가 되돌리고, `ON_ERROR_STOP`
   을 psqlrc 한 줄이 덮는다. **처방 이후에 도는 것**이 무엇인지 확인해야 한다.
3. **한 창구만 빠진다** — 사용자가 가장 많이 누르는 단건 경로에만 유예가 없었다. 같은 규칙을 쓰는 창구를
   **세어서** 목록으로 만들고 하나씩 대조하라.

★검증자가 붙지 않을 때(외부 모델 한도 초과·서버 과부하 등)는 **"독립 검토 없음"을 산출물에 명시**한다.
자체 검토로 대체했다는 사실 자체가 다음 사람이 알아야 할 정보다.

# 조회 실패를 빈 상태로 그리면 사용자가 그것을 사실로 읽는다

> **TL;DR**: `catch`에서 빈 배열이나 `0`을 대입하면 화면은 **"데이터가 없다"** 고 주장한다. 사용자는 그것을 사실로 읽고 판단한다. **"없다"와 "못 봤다"는 다른 정보**이므로 다른 표시가 필요하다 — 값 자리에 `—`와 사유를 두고, 그 상태에서 위험한 조작은 막는다.

## 증상

```ts
try {
  const res = await fetchPendingApprovals()
  pending.value = res.data
} catch {
  pending.value = []          // ← 화면에는 "승인 대기 0건"
}
```

- 승인 대기 **0건**이 "신청이 없다"로 읽힌다
- 집계 실패로 경고·오류 **0**이 "문제 없음"으로 읽힌다
- 대상 목록 조회 실패가 **"하위 폴더가 없습니다"** 로 표시된다

**토스트만 띄우는 것으로는 부족하다.** 몇 초 뒤 토스트는 사라지고 화면에는 "없음"만 남는다. 화면을 나중에 본 사람에게는 실패의 흔적이 전혀 없다.

## 원인

`catch`에서 안전한 기본값을 넣는 것은 **런타임 오류를 막기 위한 습관**인데, 그 기본값이 **의미 있는 값**(빈 목록, 0)이라 그대로 사실로 표시된다. 화면은 로딩·성공·빈 상태 셋만 알고 **실패 상태를 모른다.**

## 해결

상태를 넷으로 갈라 그린다 — **로딩 / 성공 / 비어 있음 / 실패.**

```ts
const state = ref<'loading' | 'ok' | 'empty' | 'error'>('loading')
const reason = ref('')

try {
  const res = await fetchPendingApprovals()
  pending.value = res.data
  state.value = res.data.length ? 'ok' : 'empty'
} catch (e) {
  state.value = 'error'
  reason.value = '승인 대기 목록을 불러오지 못했습니다'
}
```

표시 규칙:

- 숫자 자리에는 **`—` + 사유**를 둔다. `0`을 쓰지 않는다
- 목록 자리에는 **"불러오지 못했습니다"** 를 둔다. "없습니다"를 쓰지 않는다
- 🔴 **실패 상태에서 위험한 조작을 막는다.** 예: 용량 조회에 실패한 상태에서 재분배를 실행하면 잘못된 근거로 움직인다 — 버튼을 막고 경고를 띄운다
- **"측정 안 함"과 "조회 실패"도 다르다.** 문구를 갈라 쓴다

## 전수 조사하는 법

한 곳에서 나왔다면 같은 패턴이 여러 곳에 있다.

```bash
# catch 안에서 빈 값을 대입하는 자리 찾기
rg -n -A3 'catch' --glob '*.vue' --glob '*.ts' | rg '= \[\]|= 0\b|\.value = \[\]'
```

이미 실패 상태를 제대로 그리는 화면은 **손대지 않는다.** 고칠 곳은 "실패 표시가 아예 없는" 자리다.

## 주의

> [!WARNING]
> 같은 화면에서 **목록과 집계의 API가 다른 경우**를 놓치기 쉽다. 목록은 성공하고 집계만 실패하면, 목록은 정상으로 보이는데 요약 카드만 조용히 0이 된다.

> [!WARNING]
> 이 결함은 프론트만의 문제가 아니다. **수집기가 실패를 "대상 없음"으로 삼키면** 같은 일이 데이터 계층에서 일어난다 → [[debugfs-pseudo-file-read-buffer]]

회귀 테스트에서는 **실패 응답을 주입해 화면 문구를 검증**한다. 성공 경로만 테스트하면 이 결함은 영원히 안 잡힌다.

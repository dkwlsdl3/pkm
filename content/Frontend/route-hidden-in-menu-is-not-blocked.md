# 메뉴에서 숨기는 것은 접근 차단이 아니다

> **TL;DR**: 기능을 내리거나 권한으로 막을 때 **사이드바·네비게이션에서만 항목을 빼면**, 주소를 직접 치면 화면이 그대로 열린다. 라우트 정의와 서버 종단점이 남아 있는 한 접근은 살아 있다. 차단은 **라우트 단(과 서버)** 에서 하고, 메뉴 숨김은 그 위의 편의일 뿐이다.

## 증상

- 중단한 기능의 메뉴가 사라져 배포했는데, 즐겨찾기나 예전 링크로 들어가면 화면이 열린다.
- 열린 화면이 이미 없는 백엔드를 호출해 오류 화면·빈 화면이 뜬다.
- **전역 검색이 그 화면을 결과로 안내한다.**
- 사이드바 활성 메뉴 계산이 없는 경로를 만나 엉뚱한 항목을 활성으로 표시한다.

## 원인

메뉴 목록과 라우트 테이블이 **별개의 선언**이라서 한쪽만 고쳐도 빌드가 통과한다.
프런트 라우트 가드를 넣어도 **서버 종단점**이 살아 있으면 API 는 여전히 응답한다.

## 해결

세 겹을 모두 닫는다.

1. **라우트 정의** — 해당 경로를 제거하거나, 차단 라우트로 바꿔 안내 화면을 띄운다. 제거만 하면 404 로 떨어지는데, "없어진 기능"인지 "오타"인지 구별이 안 되므로 안내 화면이 낫다.
2. **서버 종단점** — 제거하거나 거부한다. 프런트 차단은 사용자 편의이지 보안 경계가 아니다.
3. **진입 경로 전수** — 메뉴, 전역 검색 색인, 대시보드 바로가기, 알림 링크, 문서. 하나라도 남으면 사용자는 막힌 화면으로 안내받는다.

그리고 **검사를 자동화한다** — "차단된 경로가 메뉴·검색 결과에 나타나지 않는가",
"차단된 경로로 직접 이동하면 안내 화면이 나오는가"를 시험으로 둔다. 기능 제거는
드물게 일어나서 사람 점검에 의존하면 반드시 새어 나간다.

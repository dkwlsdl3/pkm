# 릴리스 버전은 단일 소스여야 한다 — 메타패키지가 설치 불가가 된다

> **TL;DR**: 컴포넌트 패키지는 **CI 태그(`$CI_COMMIT_TAG`)** 로 빌드하는데 메타패키지의 `Requires`는 **별도 버전 파일**에서 읽는 구조라면, **태그를 다는 순간 설치가 깨진다.** 저장소에는 `pkg-<태그>`가 올라가는데 메타패키지는 옛 버전을 요구하기 때문이다. 태그가 한 번도 없었다면 이 모순은 **첫 릴리스 때 처음 드러난다.**

## 증상

- 첫 릴리스 준비 중 메타패키지 설치가 의존성 오류로 실패한다
- 컴포넌트 패키지는 저장소에 정상적으로 올라가 있다
- 그동안 CI는 계속 초록불이었다 (태그 빌드를 한 번도 안 했으므로)

```
컴포넌트 RPM 7개  →  VERSION=$CI_COMMIT_TAG 로 빌드   →  myapp-backend-1.2.1
메타패키지        →  Requires 를 version.yaml 에서 읽음 →  myapp-backend = 1.1.2  ✗
```

## 원인

버전의 출처가 **둘**이다.

1. **CI 태그** — 실제로 빌드되는 패키지의 버전
2. **버전 파일의 컴포넌트별 값** — 메타패키지가 참조하는 버전

두 값을 사람이 손으로 맞춰야 하는데, 아무도 올리지 않아 옛 값에 멈춰 있었다. **태그가 0개라 릴리스가 한 번도 없었고, 그래서 이 모순이 드러날 기회가 없었을 뿐**이다.

> 이 유형은 "평소에 안 도는 경로"에 숨는다. 릴리스·롤백·재해복구처럼 **드물게만 실행되는 경로**는 첫 실행이 곧 첫 테스트다.

## 해결

**단일 소스를 정하고 나머지를 파생시킨다.** git 태그가 자연스러운 후보다 — 이미 패키지 빌드가 그것을 쓰고 있다.

```yaml
# .gitlab-ci.yml — 버전 파일을 읽던 블록 제거, 전부 ${VERSION}
script:
  - VERSION="${CI_COMMIT_TAG#v}"
  - rpmbuild --define "version ${VERSION}" ...
```

```spec
# 메타패키지 spec — Requires 를 자기 버전으로 묶는다
Requires: myapp-backend  = %{version}
Requires: myapp-frontend = %{version}
```

```yaml
# version.yaml — 컴포넌트 블록 삭제, 사람이 읽는 한 줄만 남긴다
release_version: 1.2.1   # 빌드 입력이 아니다. 단일 소스는 git 태그다
```

같이 정리할 것:

- 버전 파일을 읽으려고 설치하던 도구(`yq` 등)도 CI에서 제거한다
- **컴포넌트별 버전 관리를 폐기**한다. 모듈이 서브레포였던 시절의 bump 스크립트가 남아 있다면 현재 구조와 맞는지 확인한다
- spec의 changelog 날짜 형식 오류는 빌드 시점에야 드러난다 → **도커 빌더 이미지로 실제 빌드해** 검증한다

## 릴리스 전 점검

- 버전을 참조하는 자리를 **전수로 찾는다**: CI 변수, spec `Version`/`Requires`, 버전 파일, 설치 스크립트, 문서
- 그중 **단일 소스에서 파생되지 않는 것이 있는가**
- 태그를 달기 전에 **태그 빌드를 한 번 흉내 내 본다**(임시 태그나 로컬 빌드)

## 주의

> [!WARNING]
> `Requires`를 버전 없이 두면(`Requires: myapp-backend`) 설치는 되지만 **버전이 섞인 조합**이 만들어진다. 구 백엔드 + 신 프론트 같은 조합이 조용히 성립하는 것이 더 나쁘다.

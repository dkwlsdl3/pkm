# GitLab 서브모듈 → 모노레포 전환 함정 모음

서브모듈 N개 + 레포별 CI를 모노레포로 합칠 때, 적대적 교차검증에서 확인된 함정들.

## 전환 방식: 제자리 개조 vs 신규 레포 병행 구축

| | 제자리 개조 | **신규 레포 + 기존 아카이브 (권장)** |
|---|---|---|
| 배포 중단 | 전환 윈도우 동안 동결 필요 | **불필요** — 스위치 전까지 기존이 정본 |
| 롤백 | 태그 앵커로 리셋 | 새 레포 폐기로 끝 |
| gitlink 함정 | deinit+.gitmodules 삭제로 부족 — 인덱스 160000 엔트리 `git rm --cached` 필요 | 해당 없음 (스냅샷 임포트) |
| 히스토리 | subtree 병합으로 보존 | 제로베이스 — 아카이브 레포에서 조회 |
| 이관 비용 | 없음 | 러너 enable·CI 변수 복사·URL 갱신 |

## CI 이식 함정 (방식 무관, 필수)

1. **상대경로 전멸**: 각 서브모듈 CI는 자기 레포 루트가 작업 디렉토리라는 전제(`cargo build`, `packaging/…`) — 모노레포에선 전 스크립트에 `cd <컴포넌트>` 또는 prefix 재작성.
2. **잡 이름 충돌**: 레포마다 `build`/`package`/`deploy` 같은 동일 잡명 → 단일 YAML 병합 시 덮어씀. `comp:build` 네임스페이스 필수.
3. **`rules:changes`는 태그 파이프라인에서 무조건 true** (push event가 없어 비교 기준 부재 — GitLab 공식 문서). 태그 릴리스 잡은 `if: $CI_COMMIT_TAG`로, 경로 필터는 브랜치 push 전용으로 분리.
4. **job-level 변수 하드코딩**: `S3_BUCKET` 등이 잡 정의에 박혀 있으면 프로젝트/그룹 변수로 못 덮는다 — 격리 환경 검증 전 grep 전수 확인.
5. **버전 계약**: 메타패키지가 컴포넌트 버전을 exact dependency로 요구하면, "태그 하나로 버전 통일"은 그 계약을 먼저 바꿔야 가능 — 1차 전환에선 기존 버전 파일 유지가 안전.

## 신규 레포 병행 구축 시 체크리스트

- 러너: project runner는 새 프로젝트에 **별도 enable** 필요 (unlocked 여부에 따라 Maintainer로 가능/Owner 필요)
- 기본 브랜치: 기존 workflow 규칙이 특정 브랜치명 전제면 새 레포 기본 브랜치를 맞출 것
- **배포 잡 자동 트리거 주의**: 기존 CI를 복사하면 기본 브랜치 push가 곧바로 실서버 배포를 때림 — 스위치 전까지 deploy 잡 manual/비활성
- 릴리스 검증은 격리 버킷/prefix에서 (repodata를 `--delete`로 갱신하는 잡은 실 리포를 오염시킴)
- 스위치 직전 기준 커밋 고정 후 스냅샷 재동기화 (병행 기간에 기존 레포에 쌓인 커밋 유실 방지)

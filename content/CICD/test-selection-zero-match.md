# 시험 선택이 0건 매치여도 잡은 green이 된다

> **TL;DR**: 이름 필터·glob으로 시험을 고르는 CI 잡은 **선택 결과가 0건이어도 exit 0** — 아무것도 실행하지 않은 것이 "전부 통과"로 보인다. 리네임·파일 이동·오타 한 번이면 시험이 통째로 증발하는데 파이프라인은 계속 green이다. **선택된 개수 자체를 별도 게이트 잡에서 단언**해야 한다.

## 증상

- 파이프라인은 늘 green인데, 시험 로그를 열어 보면 `0 passed; N filtered out` — 필터가 한 건도 못 고르고 있었다
- 검사 대상 파일을 glob으로 모으는 잡이, 그 파일들이 리네임·삭제된 뒤에도 계속 통과한다
- 회귀가 터진 뒤에야 "그 시험이 몇 주째 안 돌고 있었다"는 것을 알게 된다

## 원인

시험 러너와 셸 도구 다수가 **"고른 것이 없음"을 오류로 치지 않는다**:

- `cargo test <필터>`: 필터가 0건 매치면 `0 passed; N filtered out`으로 **exit 0**
- glob 확장: 매치 0건이면(설정에 따라) 빈 목록 또는 리터럴 문자열 — 루프가 그냥 0회 돌고 통과
- `grep -c`·`find` 기반 수집: 0건도 정상 종료 경로가 있다

선택 기준(이름·경로)은 소스와 **아무 연결이 없어서**, 소스 쪽 리네임이 선택을 조용히 끊는다. 시험을 부정 목록(`--skip`)에서 이름 선택으로 바꾸는 개선을 하다가도, 선택이 0건이 되는 순간 같은 함정에 빠진다.

## 해결

**선택 결과의 개수를 단언한다 — 그리고 그 단언은 별도 게이트 잡에 둔다.**

```bash
# 시험 잡이 아니라 게이트 잡에서: 선택이 기대만큼 잡히는지 단언
count=$(cargo test --test 'lib_*' -- --list 2>/dev/null | grep -c ': test$')
[ "$count" -ge "$EXPECTED_MIN" ] || { echo "시험 선택이 ${count}건 — 선택 기준이 소스와 어긋남"; exit 1; }
```

- **개수보다 이름이 강하다**: 존재해야 하는 시험/파일 이름을 명시 단언하면 "무엇이 사라졌는지"까지 즉시 나온다
- 단언을 `allow_failure: true` 잡 안에 두면 게이트가 아니다 — [[allow-failure-hides-fail-fast-skip]]과 같은 뿌리
- 선택 기준을 바꾸는 커밋에는 "바뀐 뒤에도 N건이 잡힌다"는 실행 증거를 함께 남긴다

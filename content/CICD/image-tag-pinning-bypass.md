# 이미지 태그 고정 검사는 표기만 바꾸면 뚫린다

> **TL;DR**: 「흐르는 태그(`:latest`, `:3`)를 쓰지 마라」를 CI 검사로 만들면, 검사는 **자기가 아는 표기 하나**만 본다. 태그 생략·`extends` 상속·레지스트리 접두사·다이제스트 위장 등 표기를 조금만 바꾸면 그대로 통과한다. 검사 대상은 **문자열 형태가 아니라 최종 해석된 이미지 참조**여야 하고, 검사 자신이 우회당하지 않는지도 시험으로 잠가야 한다.

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| 흐르는 태그 | floating tag | `:latest`·`:3` 처럼 가리키는 실물이 시간에 따라 바뀌는 태그. 같은 파이프라인이 어제와 다른 것을 실행한다 |
| 다이제스트 고정 | digest pinning | `image@sha256:…` 형태로 내용 해시를 박아 실물을 못 바꾸게 하는 것 |
| `extends` | — | GitLab CI 에서 다른 잡의 설정을 상속하는 키. 상속받은 `image:` 는 잡 본문에 안 보인다 |

## 증상

- 「전부 고정했다」고 커밋했는데 며칠 뒤 도구 버전이 혼자 올라가 잡이 깨진다.
- 검사는 초록인데 파이프라인에 흐르는 태그가 남아 있다.
- 새로 추가한 잡이 검사에 안 걸리고 흐르는 이미지를 조용히 들여온다.

## 원인

검사를 **정규식 한 줄**로 쓰면 아래가 전부 빠져나간다.

```yaml
image: alpine                      # 태그 생략 = 사실상 :latest (패턴에 ":latest" 가 없다)
image: docker.io/library/alpine:3  # 레지스트리 접두사가 붙어 패턴이 안 맞는다
image:
  name: alpine:latest              # 스칼라가 아니라 맵 형태
extends: .base-job                 # image 가 상속돼 이 잡 본문에는 안 보인다
image: alpine@sha256:0000…         # 다이제스트처럼 보이지만 존재하지 않는 값
```

더 나쁜 것은 **검사 자신의 배선**이다. 검사 스크립트가 파일 목록을 자기가 만들면, 새 파일·새 디렉터리가 목록에 안 들어가도 초록으로 끝난다. 검사가 「무엇을 검사했는지」를 출력하지 않으면 아무도 모른다.

## 해결

```bash
# 1) 문자열이 아니라 '해석된 잡 설정'을 본다 — extends 상속까지 펼쳐진 형태
glab ci config    # 또는 gitlab-ci-local --list / CI Lint API 의 merged_yaml

# 2) 펼친 YAML 에서 image 참조를 전부 뽑아 @sha256: 고정 여부를 판정
#    - 태그 생략·접두사·맵 형태를 정규화한 뒤 비교한다
#    - 다이제스트는 형식만 보지 말고 실제로 pull 가능한지 확인한다
```

- **검사가 무엇을 봤는지 출력하게 한다.** 「검사한 잡 41개 / 고정 41 / 미고정 0」처럼 개수를 찍고, 그 개수를 별도 게이트에서 단언한다. 0건 매치가 초록이 되는 경로를 막는 것과 같은 원리다.
- **검사 자체에 회귀 시험을 붙인다.** 위 우회 표기 각각을 픽스처로 넣고 「검사가 이것을 잡는가」를 시험한다. 검사 코드를 고치다 배선이 끊어지는 일이 실제로 일어난다.
- **공용 헬퍼를 조심한다.** 여러 검사가 같은 헬퍼(파일 수집·YAML 파싱)를 쓰면, 그 헬퍼를 느슨하게 고치는 순간 **관련 없는 검사들까지 한꺼번에 거짓 통과**한다.
- 도구 버전을 문서에 적었다면 그 문서도 검사 대상에 넣는다. 코드는 고정됐는데 안내서가 흐르는 태그를 권하는 상태가 흔하다.

> [!WARNING]
> `extends` 로 이미지를 상속하는 잡을 새로 추가하면, 「모든 잡이 이미지를 명시한다」류의 계약 시험이 깨진다. 상속을 허용하려면 계약을 **"펼친 뒤 고정돼 있으면 된다"** 로 다시 쓴다 — 상속을 금지하는 쪽으로 가면 중복이 늘고 결국 누군가 예외를 판다.

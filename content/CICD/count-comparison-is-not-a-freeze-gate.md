# 개수 비교는 동결 게이트가 아니다

> **TL;DR**: "이 디렉터리의 파일이 늘면 막는다"를 **개수 비교**로 구현하면 게이트가 아니라 탐지기다. 삭제 + 추가로 개수를 맞추기 · 기존 파일 내용 증식 · 없는 ref 로 0 만들기 · 총합만 보는 참조 계산 — 네 방향으로 뚫린다. 동결은 **집합과 내용(blob)** 으로 계약해야 하고, **ref 유효성은 계산보다 먼저** 확인한다.

---

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| 동결 게이트 | freeze gate | 어떤 부류의 파일이 더 늘지 않도록 막는 검사. "지금 있는 것은 두되 새로 만들지 마라" |
| blob | — | git 이 파일 **내용**을 저장하는 객체. 내용이 같으면 blob 해시가 같다 |
| ref | reference | 브랜치·태그·커밋을 가리키는 이름 |

## 증상

게이트를 넣었는데 막으려던 파일이 계속 는다. CI 는 초록이다.

## 원인 — 개수는 네 방향으로 우회된다

초판은 기준 커밋과 현재의 **파일 개수**를 비교해 "늘지 않았으면 통과"였다.

| 우회 | 무슨 일이 일어나나 |
|---|---|
| **삭제 + 추가** | 1개 지우고 1개 넣으면 66 → 66. 실증: 한 저장소의 한 달 이력에 같은 커밋에서 하나 지우고 하나 넣은 사례가 **5건** 있었다 |
| **기존 파일 증식** | 기존 초안에 수천 줄을 추가해도 **파일 수는 그대로**라 걸리는 축이 없다 |
| **없는 ref** | 존재하지 않는 커밋을 기준으로 주면 기준 목록이 비어 66 → 0 이 된다. 검사는 이것을 **"감소"** 로 읽고 종료코드 0 |
| **총합만 보는 참조 계산** | 죽은 참조를 하나 빼고 하나 넣으면 총합이 같아 통과 |

여기에 두 가지가 더 겹쳤다.

- 목록을 `ls docs/design/*.md` 로 만들면 **최상위만** 본다 — `docs/design/sub/nested.md` 는 아예 세지 않는다.
- 임시파일 이름이 고정이면 **병렬로 도는 세션끼리 서로의 중간 결과를 덮는다.**

## 해결 — 「삭제만 허용」으로 계약을 다시 쓴다

```bash
# 1) ref 유효성을 계산보다 먼저 확인한다 — 없는 ref 를 "감소" 로 읽지 않도록
git cat-file -e "${BASE}^{commit}" 2>/dev/null || {
  echo "✖ 기준 ref 가 없다. 통과시키지 않는다."; exit 2
}

# 2) 목록은 재귀로 만든다 (최상위만 보지 않는다)
git ls-tree -r --name-only "$BASE" -- docs/design | sort > "$base_list"
find docs/design -type f -name '*.md' | sort > "$head_list"

# 3) 임시파일은 mktemp + trap
tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT
```

계약은 이렇게 세운다.

- **대상 트리 ⊆ 기준 트리** — 기준에 없던 경로가 하나라도 있으면 위반(추가·교체 모두 걸린다).
- **남는 파일은 blob 이 같아야 한다** — 기존 파일 수정도 위반. 이것이 증식 우회를 막는다.
- **참조는 (참조파일, 대상경로) 쌍별 발생 횟수**를 비교한다. 총합이 아니라 쌍이어야 하나 빼고 하나 넣기가 잡힌다.
- **예외 목록은 와일드카드로 두지 않는다.** `docs/adr/*` 같은 예외는 **앞으로 쓸 파일까지 영구 면제**한다 — 실제 파일 이름으로 좁힌다.

### 검사 순서도 계약의 일부다

게이트가 **머지 뒤에** 돌면 게이트가 아니라 사후 통보다. 깨진 커밋이 이미 대상 브랜치에 들어가 있다.

```bash
git merge --no-commit --no-ff "$branch"   # 붙여만 놓고
./scripts/check-design-lifecycle.sh ...   # 머지 결과에 게이트를 건다
# 걸리면 git merge --abort → 대상 브랜치는 그대로. 통과해야 커밋한다
```

### ⚠️ 셸이 실패를 삼키는 두 자리

- **`|| true`**: allowlist 정규식이 잘못되면 `grep` 이 종료코드 2를 내는데 `|| true` 가 삼켜 **검사 전체가 통과**한다. 정규식은 쓰기 전에 한 번 컴파일해 확인한다.
- **`if ! cmd; then rc=$?`**: `!` 가 상태를 뒤집으므로 **`rc` 는 항상 0** 이다. 종료코드를 받으려면 `cmd; rc=$?` 로 받고 나서 판단한다.

### 게이트는 역검증으로만 증명된다

우회 경로를 하나씩 재현해 **기대한 종료코드가 나오는지** 확인한다. 실제로 돌린 9경로: 삭제+추가 → 1 · 없는 ref → 2 · 기존 파일 수정 → 1 · 중첩 경로 → 1 · 정상 변경 → 0 · 최종 모드 → 1 · 죽은 참조 → 1 · 잘못된 allowlist → 2 · 복구 커밋 → 0.

# rsync --checksum 은 확인 패스에만 둔다

> **TL;DR**: `--checksum` 은 **양끝 파일을 전부 읽어** 해시를 비교한다. "안전하게 하자"고 전송 인자에 넣으면 **매 백업의 비용이 데이터 전량 읽기로 뛴다.** 전송은 rsync 기본 판정(크기+수정시각)으로 두고, `--checksum` 은 **원본을 지우기 직전 `--dry-run` 확인 패스**에만 둬라. 안전 보장은 그대로 지켜지고 평상시 전송만 빨라진다.

## 개요

- **무엇**: rsync 의 변경 판정 방식 두 가지와 그 비용.
  - 기본(quick check): **크기 + 수정시각**만 본다. 메타데이터만 읽으므로 싸다.
  - `--checksum` (`-c`): **양쪽 파일 내용을 전부 읽어** 해시 비교. 확실하지만 I/O 가 데이터 크기에 비례한다.
- **왜 / 언제**: "백업 후 원본 삭제" 같은 **되돌릴 수 없는 동작 앞**에서만 확실한 확인이 필요하다.
  평상시 동기화에는 과하다.

## 동작 / 예시

```bash
# 1) 전송 — 기본 판정. 빠르다.
rsync -az --delete "$SRC/" "$DST/"

# 2) 원본을 지우기 직전에만 확인 패스. 차이가 0 이어야 한다.
DIFF=$(rsync -a --dry-run --checksum --itemize-changes "$SRC/" "$DST/" | wc -l)
[ "$DIFF" -eq 0 ] || { echo "체크섬 불일치 $DIFF 건 — 삭제 중단"; exit 1; }

rm -rf "${SRC:?}/"*
```

이렇게 하면 **"크기·시각은 같은데 내용이 다른 파일"** 이 있어도 확인 패스가 잡아 삭제를 거부한다 —
약속("체크섬 확인 후 삭제")은 지켜지고 매 전송 비용은 늘지 않는다.

## 주의

> [!WARNING]
> **확인 패스에 `--delete` 를 넣지 마라.** dry-run 이라 실제 삭제는 없지만 **삭제 예정 항목(`*deleting`)이
> 출력에 섞여 "차이 있음" 오탐**이 된다. 확인 패스의 인자는 전송용과 별도 상수로 분리하고, 왜 다른지를
> 주석에 못박아라.

> [!WARNING]
> **local 과 remote 가 인자 목록을 따로 만들면 반드시 갈라진다.** 실제로 `--checksum` 이 local 에만 있고
> 원격은 크기+시각으로 끝난 뒤 원본을 지우는 상태가 생긴다. **인자 조립을 순수 함수 하나로 뽑고** 두 경로가
> 같은 안전 플래그를 쓰게 하라. 그리고 **호출 지점이 그 함수를 쓰는지**까지 테스트하라 — 상수 값만 검사하면
> 아무도 그것을 보지 않는다.

> [!WARNING]
> `is_remote` 를 **명시 필드로 두라.** `ssh_opts.is_none()` 을 local 판정으로 쓰면 ssh 옵션이 없는 원격
> 방식이 생기는 순간 `user@host:/path` 를 로컬 디렉터리 이름으로 만들려 든다.

> [!NOTE]
> `sshpass -p <비밀번호>` 는 **argv 에 실려 같은 호스트의 아무 계정이나 `ps` 로 읽는다.**
> `-e` + 환경변수(`SSHPASS`)로 바꿔라. 더 나은 선택은 키 인증이다.

> [!NOTE]
> 파서를 만들 때는 **실제 rsync 출력으로 공격하라** — `*deleting` 줄, `.d..t` 같은 속성만 다른 표시,
> 공백 포함 경로. 가짜 샘플로 만든 파서는 운영에서 처음 틀린다.

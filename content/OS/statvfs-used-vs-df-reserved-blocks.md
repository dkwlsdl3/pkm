# statvfs 로 사용량을 재면 root 예약분이 통째로 "사용 중"이 된다

> **TL;DR**: `used = total - bavail` 로 계산하면 **비특권 사용자가 못 쓰는 예약 블록이 전부 사용량에 잡힌다.** `df` 는 그렇게 세지 않으므로 관리자가 서버에서 `df` 를 쳐서 대조하는 순간 숫자가 어긋난다. 사용량은 `total - bfree`, 여유는 `bavail` 로 갈라 쓴다.

## 증상

- 대시보드는 **8.93GB 사용(5.3%)** 이라는데 같은 마운트에서 `df` 는 **53MB(0%)** 라고 한다
- 파일을 지워도 그 차이는 줄지 않는다 — 값이 파일 총량을 따라가지 않는다
- 같은 제품 안의 다른 수집기는 `df` 와 맞는다(수집기끼리 정의가 갈려 있다)

## 원인

`statvfs`(파일시스템 통계를 읽는 POSIX 호출)가 주는 블록 수는 **셋**이고 뜻이 다르다.

| 필드 | 뜻 |
|---|---|
| `f_blocks` | 전체 블록 수 |
| `f_bfree` | **비어 있는** 블록 수 (root 예약분 포함) |
| `f_bavail` | **비특권 사용자가 할당받을 수 있는** 블록 수 (예약분 제외) |

ext 계열은 관례적으로 전체의 5% 를 root 용으로 남긴다. `bavail` 은 그 예약분을 이미 뺀 값이므로,
`total - bavail` 은 "실제로 쓴 것 + 아무도 안 쓴 예약분"이 된다. `df` 의 `Used` 열은 `f_blocks - f_bfree` 다.

⇒ 그래서 **정직하게 고치면 `used + free < total` 이 된다.** 그 차이가 예약분이고, 이것이 정상이다.

블록 수에 곱할 단위도 갈린다. `f_bsize` 는 "선호 I/O 블록 크기", **블록 수의 단위는 `f_frsize`** 다.
현대 리눅스에서는 대개 둘 다 4096 이라 값이 같아 드러나지 않지만, 계약상 맞는 것은 `f_frsize` 다.

## 해결

```text
used  = (f_blocks - f_bfree)  * f_frsize     # df 의 Used 와 같은 정의
free  =  f_bavail             * f_frsize     # 실제 할당 가능량
total =  f_blocks             * f_frsize
# 결과적으로 used + free < total (차이 = 예약분). 재구성하지 말 것 → [[derived-metric-recomputed-at-consumer]]
```

- **여유를 `f_bfree` 로 바꾸는 것으로 맞추지 마라.** 그러면 쓸 수 없는 예약분이 여유 공간으로 노출된다. 고칠 곳은 사용량 쪽이다.
- **계산을 순수 함수로 빼서 값으로 시험한다.** 실제 마운트를 재는 시험은 환경마다 값이 달라 산술을 단언하지 못하고(그렇게 적힌 주석이 흔하다), 그래서 정의가 되돌아가도 그대로 통과한다.
- 같은 제품에 수집기가 여럿이면 **정의가 갈렸는지부터 본다.** 한쪽만 고치면 화면에서 두 숫자가 계속 싸운다.

> [!WARNING]
> 이 수정은 **화면 숫자를 바꾼다.** 사용량·사용률이 줄고 여유는 예약분을 뺀 값이 된다. 임계 알림을 사용률로 걸어 뒀다면 임계도 함께 재검토해야 한다.

# 커널 링 버퍼가 넘치면 사건 수가 줄어든다

> **TL;DR**: 커널 로그(`dmesg`)를 세어 장애 건수를 집계하면, 로그가 많은 구간일수록 **오래된 줄이 밀려 나가 건수가 오히려 줄어든다.** 사건이 준 것이 아니라 **기록이 사라진 것**인데, 값만 보면 개선으로 읽힌다.

## 증상

부하를 올릴수록 장애 건수가 줄어드는 이상한 그래프가 나온다.

```
부하 낮음  → 축출 18건
부하 높음  → 축출 11건   ← 개선된 것처럼 보인다
```

## 원인

커널 링 버퍼(ring buffer, 고정 크기 순환 버퍼)는 **가득 차면 가장 오래된 줄부터 덮어쓴다.** 부하가 높은 구간은 다른 커널 메시지도 함께 쏟아지므로, 세려던 줄이 집계 시점 전에 밀려 나간다.

여기에 두 번째 함정이 겹친다 — **버퍼가 비면 카운터가 0으로 돌아간 것처럼 보인다.** 앞 구간과 뒤 구간을 각각 세어 빼는 방식이면 음수 증가분이 나오거나, 그걸 0으로 잘라 버려 사건이 통째로 사라진다.

> 조용한 실패의 전형이다. 오류도 경고도 없고, **정상적으로 계산된 잘못된 값**이 나온다.

## 해결

세 가지를 함께 넣어야 한다.

```bash
# ① 넘침 감지 — 버퍼의 가장 오래된 줄이 측정 시작 시각보다 뒤면 넘친 것이다
oldest=$(dmesg -T | head -1 | sed -n 's/^\[\(.*\)\].*/\1/p')
# oldest > 측정_시작_시각  →  이 구간의 건수는 하한값일 뿐이다

# ② 주기적 수집 — 구간 끝에 한 번 세지 말고, 측정 중 짧은 주기로 긁어 누적한다
while :; do dmesg -T | grep -i evict >> "$RAW/evict.log"; sleep 30; done

# ③ 단조 누적 — 수집한 줄을 중복 제거해 합치고, 절대 감소하지 않는 카운터로 관리한다
sort -u "$RAW/evict.log" | wc -l
```

가능하면 **커널 로그 대신 커널이 노출하는 누적 카운터**를 쓴다. 링 버퍼와 달리 덮어쓰기가 없다.

```bash
# 예: Lustre 축출 카운터 — 로그를 세는 것보다 이쪽이 정본이다
lctl get_param -n obdfilter.*.eviction_count
```

## 주의

> [!WARNING]
> 넘쳤을 가능성이 있는 구간의 건수는 **하한값**이다. 보고서에 그냥 숫자로 적으면 다른 구간과 나란히 놓여 비교돼 버린다. **"넘침 발생 — 하한"** 표시를 값 옆에 붙이거나, 아예 그 구간을 집계에서 뺀다.

건수는 **측정 창과 함께** 적는다. 창 없는 누적 건수는 인용할 수 없다.

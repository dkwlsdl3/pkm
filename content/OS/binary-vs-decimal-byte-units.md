# 1024 로 나눈 값에 TB 라벨을 붙이면 안 된다

> **TL;DR**: `KB·MB·GB·TB` 는 10진수(1000ⁿ), `KiB·MiB·GiB·TiB` 는 2진수(1024ⁿ)다. 1024 로 나눈 값에 TB 라고 적으면 **디스크 스펙·`df -H`·클라우드 콘솔이 보여주는 숫자와 어긋난다.** 기준을 하나로 정하고 계산과 라벨을 함께 맞춰라. 바꾸면 **같은 용량이 약 10% 커 보인다**(1.0 TiB → 1.1 TB).

## 개요

- **무엇**: 바이트 표기의 두 체계. IEC 접두어(Ki/Mi/Gi/Ti = 2¹⁰ⁿ)와 SI 접두어(k/M/G/T = 10³ⁿ).
- **왜 / 언제**: 저장 용량을 보여주는 화면·API·로그 어디서든. 특히 **여러 출처의 숫자를 한 화면에 놓을 때**
  기준이 갈리면 사용자가 두 숫자를 비교하다 신뢰를 잃는다.

## 동작 / 예시

| 단위 | 배수 | 1 TB 기준 차이 |
|---|---|---|
| KB / MB / GB / TB | 1000ⁿ | 기준 |
| KiB / MiB / GiB / TiB | 1024ⁿ | 같은 바이트 수를 **약 9.95% 작게** 표시 |

```
1 TiB = 1,099,511,627,776 B = 1.0995 TB
1 TB  = 1,000,000,000,000 B = 0.9095 TiB
```

**현장에서 어느 쪽을 쓰는가** — 이게 기준을 고르는 실질적 근거다.

| 출처 | 기준 |
|---|---|
| 디스크·SSD 제조사 스펙, 클라우드 스토리지 요금 | **10진수** (TB) |
| `df -h`, `ls -lh`, `free -h`, 대부분의 리눅스 도구 기본 | **2진수** (값은 1024, 라벨은 `T`) |
| `df -H`, `ls -l --si` | 10진수 |
| Windows 탐색기 | 1024 로 나누고 **GB 라고 적는다**(가장 흔한 혼란의 근원) |
| ZFS `zpool list` / `zfs list` | 2진수 |

```js
// 유일한 출처를 하나 만들고 화면들이 그것만 쓰게 한다
const UNITS = ['B', 'KB', 'MB', 'GB', 'TB', 'PB'];

export function formatBytes(v, digits = 1) {
  // ★ 모르는 값을 0 으로 단정하지 않는다
  if (v === null || v === undefined || Number.isNaN(Number(v))) return '-';
  let n = Number(v), i = 0;
  while (n >= 1000 && i < UNITS.length - 1) { n /= 1000; i += 1; }
  return `${i === 0 ? n : n.toFixed(digits)} ${UNITS[i]}`;
}
```

## 주의

> [!WARNING]
> **기준을 바꾸면 화면의 숫자가 눈에 띄게 커진다**(1024 → 1000, 약 +10%). 용량 경고 임계값, 스크린샷이
> 박힌 문서, 사용자에게 이미 안내한 값이 전부 영향을 받는다. **사전 승인을 받고 바꿔라.**

> [!WARNING]
> 이 함수가 화면마다 복사돼 있으면 기준 통일이 불가능하다. 실제로 26벌이 각자 존재하면서 **계산은 전부
> 1024 인데 라벨은 23곳이 10진수 이름**인 상태가 생긴다. 유일한 출처로 걷어내는 것이 먼저다
> → [[duplicate-code-normalized-hash-detection]]

> [!NOTE]
> **`null`·`NaN`·문자열을 `0 B` 로 표시하지 마라.** "값을 못 받았다"와 "정말 0 바이트다"는 다른 사실이고,
> 전자를 0 으로 적으면 사용자가 "비어 있다"고 오해한다. 전자는 `-`, 후자만 `0 B`.

# 프로세스 치환으로 읽으면 생산자가 죽어도 셸은 성공으로 본다

> **TL;DR**: `while … done < <(cmd)` 구조에서 셸은 `cmd` 의 종료 코드를 보지 않는다. `cmd` 가 중간에 죽으면 **그때까지 낸 출력만 읽히고 나머지는 없었던 일이 된다.** 검사 스크립트라면 "막을 사유"가 통째로 사라진 채 통과가 난다. 생산자가 마지막에 **완주 표지**를 내고 소비자가 그것을 확인해야 한다.

## 증상

- 검사 스크립트가 **종료 코드 0 에 "통과"** 를 내는데, 사실은 검사가 도중에 죽었다
- 로그에 통과 항목만 있고 실패 항목이 하나도 없다 — 진짜 없는 것인지 못 읽은 것인지 구분이 안 된다
- 게이트가 있는데 없는 것과 같아진다

## 원인

파이프라인의 종료 코드 문제로 알려진 것은 보통 `a | b` 다(`pipefail` 로 잡는다).
**프로세스 치환 `< <(cmd)` 는 그 경로가 아니다.** 셸은 `cmd` 를 별도 프로세스로 띄워 그 출력을
파일처럼 리다이렉트할 뿐이고, `while read` 루프는 **EOF 를 만나면 정상 종료**한다.
`cmd` 가 예외로 죽어서 생긴 EOF 와 다 내보내고 끝난 EOF 가 **셸에게는 똑같이 보인다.**

`pipefail` 도 이 자리는 못 잡는다 — 파이프라인이 아니기 때문이다.
`wait $!` 도 안 통한다. 프로세스 치환의 PID 는 `$!` 로 오지 않는다.

이 결함은 **평소엔 안 드러난다.** 생산자에 예외 경로가 적으면 늘 완주하기 때문이다.
그러다 "숫자를 읽는 검사"를 하나 더하는 순간, 잘못된 값 하나로 그 경로가 열린다.

## 해결

생산자가 **마지막 줄에 완주 표지를 내고**, 소비자가 그것을 못 받으면 실패로 본다.

```bash
# 생산자(예: python) 는 끝까지 갔을 때만 표지를 낸다
#   ... 판정 출력 ...
#   print("__DONE__")

saw_done=0
while IFS= read -r line; do
    [ "$line" = "__DONE__" ] && { saw_done=1; continue; }
    # 판정 처리
done < <(python3 judge.py "$@")

[ "$saw_done" -eq 1 ] || { echo "판정기가 완주하지 못했다 — 막는다" >&2; exit 1; }
```

- **표지는 생산자의 마지막 문장이어야 한다.** 중간에 내면 그 뒤에서 죽은 것을 못 잡는다.
- **임시 파일로 받고 종료 코드를 보는 방식**도 된다(`cmd > tmp; rc=$?`). 스트리밍이 필요 없다면 이쪽이 더 단순하다.
- **재현 시험을 남긴다.** 생산자가 읽을 수 없는 입력을 만나 죽는 회차를 만들어, 방어가 없으면 "통과", 있으면 "막힘"이 나오는 것을 고정한다.
- 이것은 [[verdict-missing-value-fail-open]] 의 셸 판본이다 — **"확인이 안 됐다"를 "정상이다"로 읽는 자리.**

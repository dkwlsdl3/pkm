# smartctl 종료코드는 비트마스크다 — `!= 0` 을 실패로 읽으면 안 된다

> **TL;DR**: `smartctl` 의 종료코드는 단일 성공/실패 값이 아니라 **비트마스크**다. **Bit0~2 만 "명령이 못 돌았다"** 를 뜻하고, **Bit3~7 은 명령이 제 일을 해내고 "디스크가 나쁘다"고 알리는 신호**다. `if status != 0 { 실패 }` 로 읽으면 **디스크가 나빠지기 시작한 바로 그 순간부터 수집이 멈춘다** — 가장 필요한 때 데이터가 끊긴다. 반대로 종료코드를 아예 안 보면 명령이 실패해도 그 출력을 파싱한다. 실행과 해석을 **한 모듈**로 모으고 **원시 비트를 함께 반환**하라.

## 증상

- 멀쩡히 돌던 SMART 수집이 **특정 디스크에서만** 값을 못 가져온다. 그 디스크는 마침 상태가 나빠지기 시작한 디스크다
- 또는 반대로, 장치를 열지도 못했는데 **"정상"으로 기록**된다
- 같은 저장소 안에서 자리마다 동작이 다르다 — 어떤 호출은 조금만 이상해도 죽고, 어떤 호출은 무슨 일이 있어도 통과한다

## 원인

`man 8 smartctl` 의 EXIT STATUS 절이 정의하는 대로, 종료코드의 각 비트가 서로 다른 사실을 뜻한다.

| 비트 | 뜻 | 명령은 돌았나 |
|---|---|---|
| Bit 0 | 명령줄 파싱 실패 | ❌ |
| Bit 1 | 장치를 열 수 없음 | ❌ |
| Bit 2 | SMART 명령 실패 / 검사 결과 읽기 실패 | ❌ |
| Bit 3 | **SMART 상태가 FAILING** (디스크가 곧 죽는다) | ✅ |
| Bit 4 | 과거에 임계값 이하로 떨어진 속성이 있음 | ✅ |
| Bit 5 | 현재 임계값 이하인 속성이 있음 | ✅ |
| Bit 6 | 오류 로그에 기록이 있음 | ✅ |
| Bit 7 | 자기진단 로그에 실패 기록이 있음 | ✅ |

즉 **Bit3~7 이 켜진 종료코드는 "성공적으로 나쁜 소식을 전한 것"** 이다. 이것을 실패로 접으면 디스크가 건강할 때만 값이 들어오고, 상태가 나빠지는 순간부터 수집이 끊긴다.

한 저장소 안에서 이 프로그램을 **아홉 자리**에서 부르면서 정반대 두 방식이 공존한 실제 사례가 있다 — 두 자리는 `0` 이 아니면 전부 실패로 보았고(위 함정), 나머지 일곱은 종료코드를 **아예 보지 않아** 명령이 실패해 출력이 비어도 그것을 파싱했다.

## 해결

**실행과 종료코드 해석을 한 모듈로 모으고, 모든 호출이 그것을 지나게 한다.**

```rust
// 실행 실패(하드 에러)만 가르는 마스크
const HARD_FAIL: u8 = 0b0000_0111; // Bit0~2

// 표준출력과 원시 비트를 함께 돌려준다
struct SmartctlOutput { stdout: String, raw_status: u8 }

fn is_hard_failure(raw: u8) -> bool { raw & HARD_FAIL != 0 }
```

지킬 것 넷:

1. **원시 비트를 호출자에게 그대로 넘긴다.** 표준출력에 대응하는 줄이 없는 신호(속성이 현재·과거 임계값 이하)는 비트로만 알 수 있다.
2. **판정 기본값을 "정상"으로 두지 말라.** 출력에 건강 상태 줄이 없으면 **모른다**고 기록한다 — 검사하지 않은 디스크와 정상 디스크는 다르다 → [[unknown-is-not-absent]]
3. **호출 방식을 아홉 자리에서 통일하라.** 한 자리만 `sudo` 없이 부르면 그 결과가 비고, 시리얼이 비면 수집기가 **그 디스크를 목록에서 통째로 건너뛴다.**
4. **컨트롤러 경유 장치까지 같은 통로를 지나게 한다.** 인자 종류를 열거로 넓혀 `-d sat` · `-d cciss,N` 등을 담지 않으면 그 자리들만 헬퍼를 못 쓰고 예외로 남는다 → [[smartctl-device-type-sat-cciss]]

같은 함정이 다른 CLI 에도 있다. `lfs df` 처럼 **부분 실패를 별도 종료코드로 알리는** 도구는 전부 같은 방식으로 읽어야 한다 → [[lfs-df-exit-code-partial-failure]]

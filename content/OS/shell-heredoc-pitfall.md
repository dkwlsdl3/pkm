# heredoc 조립 오염 & read-back 검증

> **TL;DR**: heredoc으로 설정파일을 쓰는 명령을 `&&`로 다른 명령과 이어붙이면, heredoc 종결자 줄이 `EOF && ...`가 되어 **명령 잔재가 파일 내용으로 흡수**된다. 파일을 쓴 뒤 **read-back(다시 읽어 검증)** 으로 잔재/빈파일/필수필드 누락을 즉시 잡아야 한다.

---

## 개요

- **무엇인가**: 코드가 동적으로 만든 셸 명령에서 heredoc과 명령 체이닝(`&&`)이 충돌하는 버그 패턴
- **왜 문제인가**: 프로비저닝 스크립트가 생성한 설정파일이 조용히 오염되고, **다음 부팅/재실행 때야** 터진다(작성 시점엔 정상처럼 보임)
- **언제 겪는가**: 코드(Rust/Python 등)가 `cat > file <<'EOF' ... EOF` 문자열을 만들어 원격에 실행시키는데, 그 뒤에 `&& systemctl enable ...`을 같은 문자열에 붙일 때

---

## 핵심 개념

### 깨지는 패턴
```bash
# 코드가 이렇게 조립하면:
cat > /etc/foo.conf <<'EOF'
key: value
EOF && systemctl enable foo     # ← 종결자 줄이 "EOF && systemctl..."가 됨
```
종결자는 **줄 전체가 정확히 `EOF`** 여야 heredoc이 끝난다. `EOF && ...`는 종결로 인식되지 않아 그 줄까지 파일 내용에 들어가고, heredoc이 안 닫히거나 뒤 명령이 실행되지 않는다. 결과: `/etc/foo.conf`에 `EOF && systemctl enable foo`가 섞이고, enable은 실행 안 됨.

### 안전한 대안
- **한 줄 명령으로**: heredoc 대신 `printf '%s' '<내용>' > file` 처럼 `&&` 체이닝에 안전한 단일 명령을 쓴다(내용에 셸 메타문자가 없도록 입력 검증 병행).
- **또는** heredoc을 독립 실행하고 뒤 명령을 별도 스텝으로 분리(체이닝 금지).

### read-back 검증 (핵심 습관)
파일을 쓴 직후 **다시 읽어서** 검증하고, 이상하면 그 자리에서 실패시킨다:
```
write(file) → content = read(file) → validate(content) → 실패 시 즉시 abort
```
검증 항목 예: 셸 잔재(`EOF`/`&&`/`$(`/`systemctl` 등 문자열), 빈 파일, 필수 필드 누락. "쓰기 API가 성공을 반환했다 ≠ 파일이 올바르다".

## 주의사항

> [!WARNING]
> 이런 오염은 작성 시점 검증(테스트·컴파일)에 안 걸린다 — 실제 조립된 명령이 원격에서 실행돼야 드러나고, 종종 **재부팅 후에야** 증상이 난다. 동적 명령 조립 코드는 회귀 테스트에 "실제로 조립된 문자열"과 "오염 샘플 reject"를 넣어둘 것.

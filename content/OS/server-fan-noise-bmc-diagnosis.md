# 서버 팬 폭음 진단

## 원칙 (성급한 단정 금지)
1. **팬은 순간 CPU 부하가 아니라 "온도 + BMC 팬 정책"에 반응한다.** load가 낮은데 팬이 최대일 수 있고, 반대로 부하 뒤에도 열 때문에 뒤늦게 고속일 수 있다. → load만 보고 범인 단정 X.
2. **어느 박스가 시끄러운지 "실물"로 먼저 확인.** 센서 숫자(RPM)만으로 추정하면 오진한다. 특히 **1U/소형 서버는 정상 baseline이 6000 RPM 안팎**으로 원래 높다 — 그 숫자를 "비정상 부스트"로 오해하기 쉽다.
3. BMC(iDRAC/XCC 등)는 **OS와 별개(아웃오브밴드)**. OS를 재부팅해도 BMC·팬 정책은 그대로. BMC 콜드리셋도 팬 정책의 근본 원인(결함/설정)은 대개 못 고친다.

## 흔한 원인
- **온도 센서/부품 읽기 누락** → 안전상 팬 최대(예: 못 읽는 PCIe/ML2 카드).
- **강제 전원차단(펜싱/AC loss) 후** BMC가 팬 프로파일을 부스트로 물어놓음.
- 팬 자체 고장 → 나머지가 보상 부스트(모든 팬 동일 RPM이면 이건 아님).
- 그냥 그 기종의 정상 baseline(대형 타워/고밀도는 원래 시끄러움).

## 진단 순서
```bash
ipmitool sdr type temperature       # CPU/흡배기 온도 — 시원한데 팬만 높으면 열 문제 아님(=정책/센서)
ipmitool sdr type fan               # 팬 RPM
ipmitool sel list | tail            # 전원/결함 이벤트 이력 (시각은 BMC TZ 주의, 종종 UTC)
# redfish 로 헬스/알림:
curl -sk -u U:P https://<bmc>/redfish/v1/Systems/1        # Status.Health
```
- 온도 정상 + 팬 고속 + Health OK → **팬 정책/센서 문제**. 무단 IPMI raw 팬제어는 **비지원·과열위험**(특히 시스템 켜진 상태). 정식 경로 = BMC 웹UI의 **thermal/fan speed profile** 설정(벤더 문서).
- 소음이 급하면: 해당 박스만 **전원 종료**가 확실(단 BMC는 대기전원으로 계속 켜져 팬을 유지할 수 있어, 완전 정지는 **AC 분리**가 필요할 수 있음).

## 교훈 (실사고)
- 전날 특정 서버를 강제 펜싱한 뒤 다른 팬 소음이 나자 **그 서버를 범인으로 지레짐작**하고 원격 조치·전원차단까지 했으나, 실물 확인 결과 **범인은 전혀 무관한 다른 서버**였다. → 인과를 섣불리 엮지 말고, 서버실에서 어느 박스인지 눈·귀로 특정하는 게 1순위.

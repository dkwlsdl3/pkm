# 단일 창 멀티세션 + worktree 통합

> **TL;DR**: 병렬 세션을 터미널 창 여러 개로 벌이면 사람이 "어느 창이 무슨 작업이었는지"를 기억해야 한다. 세션 목록을 한 창에 모으고 파일 충돌은 git worktree로 물리 분리하면, 기억과 규약에 의존하던 두 문제가 동시에 사라진다.

---

## 개요

- **무엇**: 여러 에이전트 세션을 동시에 돌릴 때의 세션 배치·충돌 방지 구조
- **왜 / 언제**: 한 레포에서 병렬로 작업을 돌리는데 세션들이 같은 파일을 서로 고치거나, 작업 위치를 놓칠 때

## 이전 방식과 그 한계 (2026-08-06 이전)

WezTerm pane·tab을 여러 개 띄우고 각 창에서 `claude` CLI를 따로 실행해 대화형으로 관리했다.

두 가지가 걸렸다.

1. **파일 충돌** — 세션들이 같은 파일을 각자 고치겠다고 나선다.
2. **위치 추적** — 어느 창이 어떤 작업을 하던 창인지 기억이 안 난다. 창 수가 늘면 헷갈린다.

1번은 brief 문서에 활성 세션 표와 세션별 점유 파일을 쓰게 하는 컨텍스트를 주입해 완화했다. 다만 이건 각 세션이 규약을 지킬 때만 성립하고, 2번은 그대로 남는다. 창의 위치는 문서에 적을 수 있는 정보가 아니다.

## 현재 방식 (2026-08-06 이후)

- 터미널 창 **하나**에서 에이전트 세션들을 띄우고, 세션 목록 화면(FleetView)에서 옮겨 다니며 진행 현황을 보고 지시한다.
- 파일이 겹칠 작업은 **git worktree로 분리**해 세션마다 별도 브랜치·별도 작업 트리를 준다.
- 별도로 둔 **통합 세션**이 완료된 worktree를 하나씩 merge 한다.

## 무엇이 나아졌나

**작업 위치를 기억할 필요가 없다.** 세션 목록이 곧 현황판이라 "어느 창이었지"가 사라진다. 이게 체감상 가장 큰 차이였다.

**충돌을 규약이 아니라 구조로 막는다.** 점유 파일 표는 세션이 그것을 읽고 지켜야 성립하는 약속이지만, worktree는 각 세션이 물리적으로 다른 트리를 보므로 서로의 파일을 고칠 방법 자체가 없다. 충돌 판정은 merge 시점으로 미뤄지고, 그때는 git이 판정한다.

## 주의

> [!WARNING]
> 충돌이 사라진 것이 아니라 merge 시점으로 옮겨졌을 뿐이다. 통합 세션은 merge 직전에 최종 diff를 다시 읽어야 한다 — 연결이 끊긴 세션이 그 사이 트리에 계속 쓰고 있을 수 있다.

worktree 분리가 항상 이득은 아니다. 세션 수가 적고 만지는 파일이 겹치지 않으면 트리를 나누는 비용(브랜치·merge 관리)이 이득보다 크다.

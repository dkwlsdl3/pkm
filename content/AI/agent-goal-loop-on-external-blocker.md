# 외부 요인에 막힌 상태의 무인 목표 루프는 반복 보고와 재시도 폭주를 낳는다

> **TL;DR**: 에이전트에게 "목표를 이룰 때까지 계속"(`/goal` + Stop 훅이 종료를 막는 구조)을 걸어 두고 자리를 비웠는데, 에이전트 혼자서는 풀 수 없는 외부 요인(계정 무효, 기다리는 상대 세션 부재)에 막히면 어떻게 될까. 에이전트는 같은 "막힘" 보고를 수십 번 되풀이하고, 확인 재시도가 대상 서버의 **로그인 횟수 제한(429)** 까지 건드린다. 루프를 걸기 전에 전제를 확인하고, 같은 원인이 반복되면 멈추고 사람을 부르게 한다.

## 증상

- 퇴근 전에 이슈 몇 개에 목표 루프를 걸어 두었다. 다음 날 보니 한 세션은 같은 "막힘: 시험 계정 로그인 불가" 보고를 수십 번 반복하고 있었다.
- 막힘을 다시 확인하려고 로그인을 반복하다가 시험 서버가 **429**(Too Many Requests, 요청이 너무 많음)를 돌려주기 시작했다.
- 다른 세션은 대기 대상(묶음 세션)이 끝난 뒤에도 Stop 훅 때문에 같은 답을 되풀이했다.

## 원인

- 시험 서버가 전날 재설치되면서 E2E(End-to-End, 실제 화면을 끝까지 조작하는 시험) 계정이 무효(401)가 됐다. 에이전트가 고칠 수 없는 전제다.
- Stop 훅은 "목표 미달이면 계속"만 알고, **"진전 없이 같은 원인"** 을 구분하지 못한다.
- 재확인 동작에 백오프(재시도 간격을 점점 늘리는 것)나 상한이 없어 외부 서버의 보호 장치를 건드렸다.

## 해결

- **걸기 전에 전제를 확인한다**: 계정 로그인, 대상 서버 상태, 기다릴 상대 세션의 존재. 하나라도 실패하면 루프를 걸지 않는다.
- **같은 막힘 N회면 멈춘다**: 보고 내용(원인)이 연속으로 같으면 루프를 끝내고 사람을 부른다(알림 등).
- **외부 시스템을 건드리는 재확인에는 백오프와 상한**을 둔다. 로그인 재시도는 계정 잠금·rate limit을 유발한다.
- 장시간 무인 실행은 "막힘 시 할 일"을 지시문에 명시한다(대기·다른 이슈로 전환·종료 중 무엇인지).

# 비율 지표는 분모가 0 일 때 가장 건강해 보인다

> **TL;DR**: 손실률·실패율 같은 비율은 **유입이 0 이면 실패도 0** 이라 `0.00% · 정상` 으로 표시된다. 수집이 완전히 멎은 상태와 완벽하게 도는 상태가 **같은 숫자**가 되는 것이다. 백엔드가 0 으로 나누지 않으려고 `0.0` 을 돌려주면 화면은 그것을 정상으로 읽는다. 비율은 값만 내보내지 말고 **분모의 크기와 관측 가능 여부**를 함께 실어라.

## 증상

- 대시보드에 손실률 `0.00% · 정상` 이 떠 있는데 실제로는 데이터가 **하나도 안 들어오고 있다.**
- 수집 통계 조회가 실패했는데도 통과율이 정상으로 보인다.
- 장애가 심할수록 지표가 더 좋아 보인다.

## 원인

비율의 분모가 0 이면 비율 자체가 성립하지 않는다. 그런데 계산 지점은 0 으로 나누는 것을 피하려고 대개 `0.0` 을 돌려주고, 표시 지점은 그 `0.0` 을 **"실패가 없다"** 로 해석한다.

같은 뿌리의 두 번째 함정이 **`Number(null)` 은 0** 이라는 것이다. 정규화 단계가 "값 없음"을 `null` 로 보존해도, 표시 단계에서 곧바로 `Number()` 로 감싸면 그 `null` 이 0 으로 접혀 화면에 `0.00% · 정상` 으로 뜬다.

## 해결

분모가 0 인 경우와 조회 실패를 **값이 아닌 상태**로 구분해 표시한다.

```ts
const lossRatePercent = computed(() => {
  if (statsError.value) return null            // 조회 실패 — 값이 아니라 상태다
  // 🔴유입이 0 이면 비율이 성립하지 않는다. 백엔드는 이때 0.0 을 돌리므로 여기서 걸러야
  //   「0.00% · 정상」으로 보이지 않는다 — 상단 통과율과 같은 판정.
  if (lossIntakeTotal.value === 0) return null
  const raw = ingestStats.value.lossRatePercent24h
  // ⚠️`Number(null)` 은 0 이다 — 정규화가 보존한 null 이 여기서 0 으로 접히면 안 된다
  return raw === null ? null : Number(raw)
})
```

- 비율을 내보내는 API 는 **분자·분모를 함께** 싣는다. 소비자가 "분모가 0" 을 스스로 판정할 수 있어야 한다.
- 화면에서는 `—`, `측정 불가`, `유입 없음` 처럼 **0% 와 다르게** 보이는 표기를 쓴다.
- 손실을 여러 경로에서 세는 경우(검증 거부·레이트리밋·저장 실패·격리 등) **같은 시간 창**에서 세고 분해를 함께 보여줘야 한다. 창이 갈리면 분자와 분모가 다른 것을 재게 된다 → [[ratio-of-mismatched-windows]]

> [!WARNING]
> 재전송으로 생긴 **중복(dedup)** 은 멱등 처리의 정상 결과라 손실로 세지 않는다. 다만 그 기준을 백엔드와 화면이 똑같이 써야 한다 — 한쪽만 빼면 두 화면의 숫자가 갈린다 → [[derived-metric-recomputed-at-consumer]]

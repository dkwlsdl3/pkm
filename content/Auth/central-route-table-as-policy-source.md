# 중앙 라우트표을 정책의 정본으로 선언한다

> **TL;DR**: 라우트별 권한 메타데이터를 모은 중앙표는 **"실제 배선"을 적는 문서가 아니라 "정책"을 적는 문서**다. 그러면 표와 핸들러 시그니처가 **의도적으로 다를 수 있고**, 그 예외는 명시 목록 + AST 검사로 지킨다. 대신 반드시 확인할 것 — 표의 정책 축을 **강제 로직이 전부 읽는지**. 축이 구조체와 테스트 픽스처에만 존재하고 런타임 소비자가 0개인 상태가 실제로 생긴다.

---

## 왜 이 결정이 필요한가

인가를 미들웨어 extractor로 표현하면 표현할 수 없는 라우트가 남는다. 전형적인 예:

- **인증 토큰이 쿼리스트링에 있는 WebSocket** — extractor를 붙일 수 없어 관리자 검사가 **함수 본문**에 있다
- 그 결과 중앙표에는 `fixed_capability = None`(특별 권한 불필요)으로 적히고
- 표만 읽는 fail-closed 매트릭스가 켜지면 **조회 권한만 가진 역할이 원격 루트 셸을 통과한다**

즉 "표 = 배선의 거울"로 두면 배선이 표현 못 하는 정책을 표에 적을 수 없다.

## 결정: 표는 정책을 적는다

```rust
// 표: 정책 사실을 적는다 (핸들러에 RequireCap 인자가 없어도)
route!(terminal_ws, Category::System, fixed_capability = Some(Capability::TerminalExec)),
```

- 강제 로직은 표의 값을 **반드시 읽는다**
- 표와 핸들러 시그니처가 다를 수 있음을 **ADR로 명문화**한다(나중에 읽는 사람이 "불일치 = 버그"로 오판하지 않도록)
- 새 라우트 추가 시 지킬 절차를 규칙으로 고정한다(등록 매크로 형태 · 표 등재 · 골든 갱신)

## 예외를 검증으로 지킨다

기존 불변식("표에 capability가 있으면 핸들러에 `RequireCap` 인자가 있어야 한다")을 그냥 완화하면 검증이 느슨해진다. 예외 목록을 두되 **그 예외에 대해 더 강한 검사로 대체**한다:

```
INTERNALLY_ENFORCED_CAPABILITIES = [terminal_ws, ...]
  → 각 항목에 대해 "함수 본문에 실제 가드 호출(ExprCall)이 존재함"을 AST로 증명
  → 예외 항목이 나중에 RequireCap으로 배선되면 "목록에서 제거하라"며 FAIL
```

**텍스트 검색이 아니라 호출 노드 확인**이므로 가드 이름을 문자열·주석으로 위장해도 잡힌다(실증 확인). 검증 강도는 오히려 올라간다.

## 반드시 확인할 것 — 정책 축에 런타임 소비자가 있는가

이 결정의 가장 위험한 실패 모드다. 표에 정책 축을 여러 개 두면 **강제 로직이 그중 일부만 읽는** 상태가 조용히 생긴다.

실제로 축 2개(민감도 표시, 추가 카테고리 AND 조건)가 **구조체 정의·테스트 픽스처·표 데이터에만 존재하고 런타임 소비자가 0개**였다. 결과:

- 민감도 축 무시 → 낮은 권한 역할이 GET 응답에서 **비밀번호를 평문 수신**(강제를 켜기 전에는 최고 권한만 도달했으므로 **권한 회귀**였다)
- AND 축 미구현 → 주 카테고리만 보고 통과시켜, 한쪽 권한만 가진 역할이 타 카테고리 쓰기를 실행

**테스트 수백 개가 green이었던 이유**: 인가 단위테스트 픽스처가 **항상 추가 카테고리를 빈 배열**로 세팅했고, 민감도 테스트는 구조체 조립만 확인했다. 즉 green이 두 축의 **실행을 증명하지 않았다.**

### 대책

```
- rg로 각 축의 런타임 소비자를 전수 확인한다 (0개면 정책이 적혀만 있는 것)
- 픽스처를 손으로 채우지 말고 표에서 런타임 열거하는 테스트를 쓴다
  → 새 라우트가 추가돼도 자동으로 덮인다
- 골든 목록(민감 라우트 등)을 두어 목록이 늘면 FAIL시켜 처리를 강제한다
- 뮤테이션으로 확인한다 (AND 체인 제거 → FAIL / 마스킹 되돌림 → FAIL)
```

## 곁가지 함정: 마스킹과 저장 경로

민감 필드를 응답에서 빼려고 **원본 구조체에 `skip_serializing`을 붙이면 안 된다** — 같은 구조체를 직렬화해 설정 파일에 저장하는 경로가 있으면 **저장 시 값이 사라져 기능이 조용히 깨진다**. 응답 전용 DTO를 분리하고, 대신 `has_xxx: bool`을 제공해 UI가 "설정됨"을 표시할 수 있게 한다.

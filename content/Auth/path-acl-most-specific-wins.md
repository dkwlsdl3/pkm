# 경로 기반 권한은 최장 일치가 이겨야 한다

> **TL;DR**: 상위 폴더 허용과 하위 폴더 제한이 동시에 걸릴 때 **상위가 이기면 하위 제한은 존재하지 않는 것과 같다.** 가장 구체적인(경로가 가장 긴) 규칙이 이기도록 판정해야 한다.

## 증상

- 하위 폴더에 "쓰기 금지"를 걸어놨는데 파일이 써진다.
- 상위 폴더 권한을 회수하면 하위 제한이 그제서야 동작한다 — 즉 **하위 규칙이 조회조차 안 되고 있었다.**
- 화면의 권한 설정 목록에는 제한이 정상적으로 보인다. 설정은 저장돼 있고 판정만 무시한다.

## 원인

경로 권한을 **조상 경로부터 훑으면서 처음 만난 허용에서 멈추는** 방식으로 판정했다.

```text
등록된 규칙
  /data/team          쓰기 허용   (팀원 전체)
  /data/team/secret   쓰기 금지   (특정 사용자 제한)

/data/team/secret/x.txt 쓰기 요청
  → /data 조회        규칙 없음
  → /data/team 조회   허용  ← 여기서 멈춤. 허용 반환
  → /data/team/secret 은 아예 조회되지 않음
```

"조상 중 하나라도 허용이면 허용"은 **파일 공유 폴더의 상속 모델로는 자연스러워 보이지만 제한을 표현할 수단이 사라진다.** 하위에 무엇을 걸어도 상위 허용이 먼저 잡히기 때문이다.

⚠️ 이 결함은 **정상 시나리오 테스트로는 절대 안 잡힌다.** 상위만 있거나 하위만 있는 경우는 다 맞게 동작한다. **둘이 겹칠 때만** 틀린다.

## 해결

**모든 조상 규칙을 수집한 뒤, 경로가 가장 긴 것 하나를 고른다.**

```text
1. 요청 경로의 조상 전체에 걸린 규칙을 모은다 (조기 종료 금지)
2. 경로 길이(세그먼트 수) 내림차순 정렬
3. 가장 구체적인 규칙 하나의 판정을 그대로 쓴다
```

정해야 할 것 두 가지:

- **같은 경로에 여러 주체(사용자·그룹)의 규칙이 겹칠 때 무엇이 이기는가.** 흔한 선택은 "사용자 규칙이 그룹 규칙을 이긴다", 또는 "같은 구체성에서는 거부가 이긴다(deny wins)". 어느 쪽이든 **문서로 못 박아야** 판정 코드와 화면 설명이 어긋나지 않는다.
- **아무 규칙도 안 걸릴 때의 기본값.** 허용이면 규칙 누락이 곧 개방이 된다. 저장소 권한이라면 기본 거부가 안전하다.

관련해서 **조회 실패는 "규칙 없음"이 아니다.** 조회가 실패했을 때 기본값으로 흘리면 DB 장애가 곧 권한 개방이 된다 → [[unknown-is-not-absent]]

## 같은 판정 규칙을 쓰는 다른 곳

최장 일치는 경로 권한만의 규칙이 아니다. **계층 구조에 규칙을 붙이는 모든 곳**에서 같은 문제가 나온다 — 라우팅 테이블의 프리픽스 매칭, 사이드바 활성 메뉴 판정, URL 라우팅, 방화벽 규칙. 판정 방식이 다르면 **같은 제품 안에서 화면과 백엔드가 서로 다른 답을 낸다.**

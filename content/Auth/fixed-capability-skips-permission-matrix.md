# 고정 capability 가 붙은 라우트는 위임 매트릭스를 보지 않는다

> **TL;DR**: 같은 보안 카테고리의 읽기 창구라도, **고정 capability**(그 라우트에 못 박은 권한)가 붙어 있으면 권한 매트릭스를 건너뛰고 최고 등급만 통과한다. 화면이 그런 창구로 갈아타면 **카테고리를 위임받은 관리자에게서만** 화면이 깨진다 — 개발자 계정으로는 재현되지 않는다.

## 증상

- 관리 화면의 한 열(예: 역할 이름)이 **일부 관리자에게만** 비거나 원문 키로 표시된다
- 최고관리자로 로그인하면 정상이라 재현이 안 된다
- 두 API 가 같은 카테고리인데 한쪽만 403 이다

## 원인

권한 판정이 **두 경로**를 갖기 때문이다.

| 라우트 메타 | 판정 경로 | 통과 대상 |
|---|---|---|
| `fixed_capability: None` | 카테고리 권한 **매트릭스**를 본다 | 그 카테고리를 위임받은 역할 포함 |
| `fixed_capability: Some(X)` | 매트릭스를 **보지 않고** X 를 요구한다 | X 를 가진 최고 등급만 |

같은 "보안 카테고리 읽기"인데 **사용자 목록**은 앞쪽이고 **역할 목록**은 뒤쪽이면,
화면이 하드코딩하던 목록을 "이미 있는 역할 목록 API"로 갈아타는 순간
위임 관리자에게서 그 열이 깨진다. **두 API 가 같은 카테고리에 있다는 사실이 착각을 만든다** —
카테고리가 아니라 라우트 메타가 판정을 정한다.

## 해결

- **갈아타기 전에 두 라우트의 메타를 대조한다.** 카테고리가 같다는 것은 근거가 아니다. `fixed_capability` 유무와 값을 직접 확인한다.
- 화면에 필요한 최소 정보만 주는 **별도 조회 창구를 연다.** 실측 사례에서는 역할 목록 카탈로그를 관리자 등급으로 열되 **권한 매트릭스 · 시스템 역할 여부 · 사용자 수는 싣지 않았다.** 판정에 쓰이는 민감한 열을 빼면 등급을 낮춰도 안전하다.
- **위임 역할 계정으로 확인한다.** 최고 등급 계정으로만 보면 이 결함군은 영영 안 보인다.
- **조회 실패를 빈 목록과 다르게 그린다.** 실패를 빈 배열로 흘리면 "역할 없음"처럼 보이고 라벨 자리에 키 원문이 뜬다. 실패하면 안내를 띄우고 그 기능을 잠근다.
- 화면이 목록을 **하드코딩하고 있었다면** 그 자체가 별개의 결함이다 — 항목이 늘어도 화면이 따라가지 않고, 다른 화면에서 배정한 값을 이 화면 필터로 못 찾는다. 선택지 · 필터 · 라벨 생성을 **유틸로 분리**하면 페이지를 마운트하지 않는 시험 설정에서도 "항목이 늘거나 줄어도 화면이 따라간다"를 잠글 수 있다.

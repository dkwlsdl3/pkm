# 경로 권한 검사가 정규화보다 먼저면 표기 변형으로 뚫린다

> **TL;DR**: 같은 위치를 가리키는 경로 문자열은 여러 가지다. 권한 검사를 **정규화 전에** 하면 검사 대상 문자열과 실제 접근 대상이 달라져 검사가 통째로 건너뛰어진다. **정규화 → 검사 → 접근** 순서를 고정한다.

## 증상

- 권한이 없는 사용자가 특정 표기법으로 요청하면 접근이 성공한다.
- 정상 표기(`/data/team/docs`)는 거절되는데 변형 표기(`/data//team/docs`, `/data/team/./docs`, 끝에 슬래시가 붙은 형태)는 통과한다.
- 로그에는 "권한 검사 통과"가 찍혀 있어서 검사가 안 돈 것처럼 보이지 않는다 — **돌긴 돌았고, 다른 문자열을 봤을 뿐이다.**

## 원인

ACL(Access Control List, 접근 제어 목록)이 **경로 문자열을 키로** 저장돼 있고, 검사는 문자열 비교(또는 접두사 매칭)로 이뤄진다. 여기서 두 단계의 순서가 뒤집혀 있었다.

```text
잘못된 순서:  요청 경로 → ACL 조회(문자열 그대로) → 정규화 → 파일시스템 접근
올바른 순서:  요청 경로 → 정규화 → ACL 조회 → 파일시스템 접근
```

파일시스템은 `//`나 `/./`를 알아서 접어서 같은 위치로 해석하지만, **문자열 비교는 안 접는다.** 그래서 ACL에 등록된 `/data/team/docs`와 요청의 `/data//team/docs`가 "다른 경로"로 판정되고, 등록된 제한이 조회되지 않아 **제한 없음 = 허용**으로 흘러간다.

같은 뿌리의 변형:
- 상대 경로 요소(`..`) — 정규화 전에는 상위 탈출이 보이지 않는다
- URL 인코딩(`%2F`) — 디코딩 전에 검사하면 마찬가지
- 심볼릭 링크 — 문자열 정규화만으로는 부족하고 실제 해소(`realpath`)까지 필요할 수 있다
- 대소문자 구분 없는 파일시스템에서의 대소문자 변형

## 해결

**검사 함수에 정규화되지 않은 경로가 들어올 수 없게 만든다.** 순서를 지키자는 규약으로는 부족하다 — 호출처가 늘어나면 반드시 하나는 빠뜨린다.

- 정규화된 경로만 담는 **별도 타입**을 만들고, ACL 검사 함수는 그 타입만 받는다. 생성자는 정규화를 거쳐야만 통과시킨다.
- 원시 문자열을 받는 진입점은 **관문 하나로 좁힌다**. 관문 밖에서는 경로를 만들 수 없게 한다.
- 정규화가 실패하면(해소 불가·범위 밖) **거절**한다. 실패를 "제한 없음"으로 흘리면 [[unknown-is-not-absent]]와 같은 함정이 된다.

⚠️ **정규화가 파일시스템 접근을 동반하는지 확인한다.** 순수 문자열 정규화(lexical)는 심볼릭 링크를 못 푼다. 링크가 신뢰 경계를 넘을 수 있는 환경이면 실제 해소가 필요하고, 그 경우 **해소한 경로로 검사한 뒤 그 경로로 접근**해야 한다(검사와 접근 사이에 링크가 바뀌는 TOCTOU 창을 줄이려면 열어둔 파일 디스크립터 기준으로 다루는 편이 낫다).

**검증은 변형 표기 목록으로 한다.** 정상 경로만 테스트하면 이 결함은 영원히 안 잡힌다.

```text
검사 대상 표기 변형 (최소):
  /a/b        정상
  /a//b       중복 슬래시
  /a/./b      현재 디렉터리 요소
  /a/c/../b   상위 탈출 후 복귀
  /a/b/       후행 슬래시
  /a/%2Fb     인코딩 잔여
```

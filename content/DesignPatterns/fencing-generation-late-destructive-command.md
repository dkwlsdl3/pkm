# 늦게 도착한 파괴 명령은 세대(generation) 값으로 거절한다

> **TL;DR**: 조정자가 보낸 파괴 명령(볼륨 삭제·스냅샷 롤백 등)은 네트워크 지연·재시도 때문에 **잠금이 이미 다른 주인에게 넘어간 뒤에 실행 노드에 도착할 수 있다.** 명령에 **단조 증가하는 세대 값(fencing token)** 을 실어 보내고, 노드가 자기가 아는 최신 세대보다 낮은 명령을 거절하게 해야 한다. 잠금만으로는 막지 못한다.

## 개요

- **무엇**: 자원을 잡을 때마다 1 증가하는 정수를 발급해 잠금과 함께 저장하고, 그 잠금으로 내보내는 모든 명령에 같이 실어 보낸다. 실행 측은 **받은 세대 < 자기가 본 최대 세대** 이면 실행하지 않고 거절한다.
- **왜 / 언제**: 분산 잠금은 "지금 내가 주인인가"만 답한다. 명령이 **발송된 뒤 도착하기까지** 주인이 바뀌는 구간은 잠금이 덮지 못한다. 결과가 되돌릴 수 없는 파괴적 작업(삭제·롤백·영구 비활성화)에서만 문제가 드러난다 — 읽기는 늦게 도착해도 손해가 없기 때문이다.

## 동작 / 예시

```text
t0  A 가 volume-1 잠금 획득 → generation = 7
t1  A 가 노드로 "volume-1 삭제 (gen=7)" 발송 — 네트워크에서 지연
t2  A 가 죽음 → 잠금 만료 → B 가 획득 → generation = 8
t3  B 가 volume-1 을 새 데이터로 재생성 (gen=8)
t4  t1 의 명령이 도착. 노드가 본 최대 세대는 8 > 7 → 거절
    ← 세대가 없으면 여기서 B 의 데이터가 삭제된다
```

## 주의

> [!WARNING]
> **잠금 해제 조건이 "작업이 끝났다"이면 세대가 있어도 새어 나간다.** 노드 호출 결과를 모르는 채(타임아웃·연결 끊김) 잠금을 놓으면, 그 명령은 여전히 노드에서 실행 중일 수 있다. 결과 미확정 상태에서는 **노드 종료를 확인한 뒤에만** 잠금을 놓아야 한다 → [[timeout-is-unknown-not-failure]]

> [!WARNING]
> 같은 작업이 같은 자원을 **추가로 획득**할 때 세대를 올리면, 이미 보낸 자기 명령이 무효가 된다. 재진입 획득은 세대를 올리지 않도록 구별해야 한다.

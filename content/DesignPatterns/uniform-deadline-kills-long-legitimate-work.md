# 일괄 마감은 종류별 정상 소요가 다른 작업을 죽인다

> **TL;DR**: 종류에 따라 정상 소요가 몇 분에서 몇 시간까지 갈리는 작업에 **하나의 마감**을 걸면, 오래 걸리는 종류는 **멀쩡히 도는 중에 매번 시간 초과로 덮인다.** 게다가 그 판정이 실제 결과 확인보다 먼저 돌면 되살릴 방법도 없다. 마감을 **요청마다 계산해 행에 적고**, **상태 전이와 같은 문장에서** 박고, 기준 시각은 **전부 DB 쪽**으로 둔다.

## 증상

- 빠른 검사는 잘 도는데 **정밀 검사만 항상 "시간 초과"** 로 끝난다
- 실제로는 하드웨어가 정상적으로 돌고 있었고, 조금 뒤 결과도 남는다 — 그런데 요청은 이미 **종단 상태로 닫혀** 있어 아무도 그 행을 못 건드린다
- 대용량 장치일수록 재현율이 높다

## 원인

마감이 **작업 종류와 무관하게 일괄**로 걸려 있었다. 예: 디스크 자기진단에서 빠른 검사는 2분, 확장 검사는 대용량 디스크에서 **정상적으로 수 시간**인데 마감은 둘 다 2시간.

두 번째 문제는 **판정 순서**다. 마감 판정이 하드웨어 기록 확인보다 먼저 돌면, 실제 결과가 도착하기 전에 요청이 실패로 닫힌다. 종단 상태는 되돌리지 않는 것이 보통이므로 **그 뒤에 온 진짜 결과는 갈 곳이 없다.**

## 해결

### 1. 마감을 요청마다 행에 적는다

```sql
ALTER TABLE selftest_request ADD COLUMN deadline_at TIMESTAMPTZ;
```

### 2. 상태 전이와 **같은 문장**에서 박는다

```sql
UPDATE selftest_request
   SET status = 'running',
       deadline_at = now() + $1::interval   -- 종류별 폴백
 WHERE id = $2;
```

두 문장으로 나누면 **그 사이에 프로세스가 죽었을 때 마감 없는 행이 남는다.**

### 3. 장치가 알려 주는 값이 있으면 그것으로 좁힌다

`smartctl` 로 시작하는 경로는 장치가 보고한 **권장 폴링 시간**이 있다. 그 값으로 마감을 좁히고, ioctl·SG_IO 처럼 그 값이 없는 경로는 폴백을 쓴다.

- 장치값이 `0` 이거나 안 읽히면 폴백
- 여유 계수를 곱한 뒤 **폴백 상한을 넘으면 잘라 낸다** (장치가 비상식적인 값을 줄 수 있다)

### 4. 마감이 NULL 인 행을 따로 닫는다

배포 전에 시작된 행은 마감이 없다. 이것을 빠뜨리면 **구 버전이 시작한 행이 영영 안 닫힌다.** 종류별 상한으로 별도 정리 경로를 둔다.

### 5. 기준 시각은 전부 DB 쪽

데몬 호스트의 시계로 계산하면 두 시계가 어긋난 만큼 **조기·지연 종료**가 난다. `now()` 를 DB 에서 부르고 비교도 DB 에서 한다 → [[sqlx-timestamptz-string-decode]]

### 배포 순서 주의

⚠️ **마이그레이션 먼저, 새 실행 주체는 나중.** 설치 도구가 SQL 을 컴파일 시점에 내장하는 구조라면 **SQL 파일만 배포해서는 반영되지 않는다** → [[migrations-replayed-in-full]]

## 함께 봐야 할 것

마감을 고쳐도, **결과를 못 읽은 것이 "끝남"으로 접히면** 같은 사고가 다른 경로로 재현된다. 실행 상태 판정을 **실행 중 / 끝남 / 조회 불가** 삼값으로 가르고, 조회 불가면 아무것도 닫지 말고 다음 주기에 다시 본다 — **상한은 행에 박힌 마감이 맡는다** → [[timeout-is-unknown-not-failure]] · [[unknown-is-not-absent]]

# 관측에 실패한 것을 관측값으로 적으면 방어가 통째로 꺼진다

> **TL;DR**: 「모름을 없음으로 접지 말라」([[unknown-is-not-absent]])의 **저장 계층 판본**. 실패 폴백값이 화면을 잠깐 속이는 데서 끝나지 않고 **DB 에 실측치와 같은 칸으로 적히면**, 그 뒤로는 되돌릴 방법이 없다. 임계치 경보는 영구히 꺼지고, 나중에 코드를 고쳐도 **이미 0 으로 적힌 과거 행**이 남아 계속 정상으로 읽힌다. 실패는 값이 아니다 — 스키마에서 `NULL`/`Unknown` 을 허용하고, 되돌릴 때는 데이터 마이그레이션을 같이 계획한다.

## 용어

| 표기 | 원어 | 뜻 |
|---|---|---|
| fail-open / fail-closed | — | 판정 불가일 때 통과시키는 설계 / 막는 설계 |
| inode | index node | 파일시스템에서 파일 하나를 가리키는 메타데이터 단위. 개수 고갈도 용량 고갈처럼 장애가 된다 |

## 증상

- 저장소 사용률 경보가 **한 번도 울리지 않는다.** 대시보드에는 용량 0, inode 0 이 찍혀 있다.
- 「이 디스크는 아무도 안 쓴다」고 판정해 파괴적 작업이 진행됐는데, 실제로는 남의 자원이었다.
- 동시 실행 가드가 「진행 중 아님」이라며 두 번째 실행을 들여보낸다.

공통 형태는 하나다.

```rust
// 🔴 실패가 "관측된 사실"로 둔갑한다
let pools = list_zfs_pools().unwrap_or_default();   // 조회 실패 → 빈 목록 → "풀이 없다"
let used  = measure_capacity(&path).unwrap_or(0);   // 측정 실패 → 0    → "여유 충분"
let busy  = query_running_job().unwrap_or(false);   // 조회 실패 → false → "진행 중 아님"
```

## 원인

`unwrap_or` / `?: 기본값` / 빈 컬렉션 폴백은 **호출부의 편의**를 위한 장치인데, 그 값이 그대로 **기록·경보·판정의 입력**이 된다. 세 층이 서로를 못 본다.

1. 수집 계층: 실패를 삼키고 기본값을 돌려준다 (여기까지는 크래시를 막는 합리적 선택으로 보인다)
2. 저장 계층: 그 기본값을 **실측치와 구별 없이** 같은 칸에 적는다 — 여기서 정보가 영구히 사라진다
3. 판단 계층: 적힌 값을 실측으로 믿는다. 0 은 「여유」, 빈 목록은 「없음」, false 는 「안 돎」

특히 위험한 것은 **기본값이 하필 "안전해 보이는 쪽"** 이라는 점이다. 0 은 경보 임계 아래고, 빈 목록은 충돌 없음이고, false 는 가드 통과다. 장애가 심할수록 지표가 좋아 보인다.

## 해결

**실패를 값으로 접지 말고 상태로 남긴다.**

```rust
// 저장 계층: 실측치와 미측정을 다른 값으로
struct PoolUsage {
    used_bytes:  Option<u64>,   // None = 못 쟀다 (0 과 다르다)
    inodes_used: Option<u64>,
    measured_at: Option<DateTime<Utc>>,
}

// 판단 계층: 미측정은 통과가 아니라 차단
match usage.used_bytes {
    Some(b) if b < threshold => Ok(()),
    Some(_)                  => Err(CapacityExceeded),
    None                     => Err(Unmeasured),   // 🔴 파괴적 작업은 여기서 멈춘다
}
```

- **DB 칼럼에도 이 구분을 둔다.** `NOT NULL DEFAULT 0` 은 이 버그를 스키마 수준에서 못박는 장치다.
- 경보 규칙은 「값이 임계를 넘으면」이 아니라 **「정상임이 확인되지 않으면」** 으로 쓴다. 미측정 자체가 경보 대상이다.
- 파괴적 작업(포맷·삭제·비활성화)의 선행 조건은 전부 fail-closed 로 뒤집는다. 「위험하다는 증거가 없음」이 아니라 **「안전하다는 증거가 있음」** 을 요구한다.
- 화면에서도 `0` 과 `—(미측정)` 을 다르게 그린다. 숫자로 그리는 순간 사람도 실측으로 읽는다.

> [!WARNING]
> `unwrap_or_default()` 를 지우는 것만으로는 안 끝난다. **이미 DB에 0 으로 적힌 과거 행**이 남아 있고, 경보는 그 값을 계속 정상으로 읽는다. 되돌릴 때 데이터 마이그레이션을 함께 계획한다.

# 오류 문구 판정을 낱말 부분일치로 하면 뒤집힌다

> **TL;DR**: 상대가 내려보낸 오류 문구로 종류를 가릴 때 낱말 하나(`timeout` 등)로 부분일치시키면, **메시지에 섞여 오는 데이터(대상 이름·경로)에 그 낱말이 들어 있는 순간 판정이 뒤집힌다.** 영구 오류가 "미지" 로 분류되면 실패가 조용히 방치된다. 표식은 **문장 단위**로, 실제로 나오는 형태만 등록한다.

---

## 증상

원격 노드가 내려보낸 오류를 "상한 초과(미지)" 와 "확정 실패" 로 가르는 판정이,
**권한 오류를 미지로 읽었다.**

```
표식: "timeout"
메시지: "target timeout-OST0001: Permission denied"
              ^^^^^^^  대상 이름에 들어 있을 뿐이다
⇒ 상한 초과로 분류 → "돌고 있을 수 있으니 기다린다" → 아무도 고치지 않는다
```

## 원인

오류 문구는 **고정 문자열 + 데이터**의 조합이다. 데이터 부분은 사용자·운영자가 정한 이름이
그대로 실려 오므로 **어떤 낱말이든 들어올 수 있다.** 판정용 표식을 낱말 하나로 잡으면
데이터 영역과 구분이 안 된다.

여기에 [[timeout-is-unknown-not-failure]] 가 겹치면 피해가 커진다 —
"미지" 분류는 보통 **아무것도 하지 않고 기다리는** 처리라, 오분류가 침묵으로 이어진다.

## 해결

**실제로 나오는 문장 단위**로만 표식을 등록한다.

```rust
/// 노드가 "상한을 넘겼다" 고 알리는 문구의 표식.
///
/// 🔴 낱말 하나(`timeout`·`타임아웃`)를 넣지 마라. 메시지에는 대상명·경로가 섞여 오므로
/// `target timeout-OST0001: Permission denied` 같은 영구 오류가 미지로 뒤집힌다.
const NODE_TIMEOUT_MARKERS: &[&str] = &[
    // 마운트·해제·포맷 창구가 내는 형식
    "안에 끝나지 않았습니다",
    // 복구 경로가 내는 "… 타임아웃(120초)" 형식
    "타임아웃(",
];

fn node_reports_timeout(message: &str) -> bool {
    NODE_TIMEOUT_MARKERS.iter().any(|m| message.contains(m))
}
```

- `"타임아웃("` 처럼 **뒤따르는 구분자까지 포함**하면 낱말만 든 데이터와 갈린다
- 표식은 한 곳에 모으고, **문구를 내는 쪽과 읽는 쪽 양쪽 시험이 계약을 잠근다**

## 주의

> [!WARNING]
> **문구 대조는 마지막 수단이다.** 가능하면 구조화된 값(오류 코드·enum·HTTP 상태)으로 받는다.
> 문구는 번역·문장 다듬기 한 번에 조용히 깨진다 → [[cli-output-locale-translated-header]]

> [!WARNING]
> **같은 판정이 여러 호출 경로에 흩어져 있는지 확인하라.** 한 경로에만 있으면 나머지 경로는
> 같은 문구를 받고도 종류를 구분하지 못한다 — 표식을 공용 상수로 올릴 때 호출부를 전수로 센다.

> [!WARNING]
> **상대의 문구를 고칠 때 이 표식도 함께 본다.** 양쪽이 별개 저장소면 계약이 조용히 갈라진다.

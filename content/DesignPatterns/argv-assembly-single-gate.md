# 명령 인자 조립을 한 곳에 가두지 않으면 플래그 규약은 지켜지지 않는다

> **TL;DR**: "이 CLI 는 항상 `--안전플래그` 를 붙여서 부른다" 는 규약을 **호출 지점마다 지키게** 하면 반드시 샌다. `sudo psql …` 처럼 **실제로 뜨는 프로세스와 인자가 갈리는** 경우, 플래그를 잘못된 위치에 두면 **앞의 프로그램이 받아 먹는데 소스를 훑는 검사는 통과시킨다.** 인자 조립을 **한 모듈 안에 가두고 밖으로는 연산만** 내보내라 — 플래그 상수·실행 파일 이름·인자 목록을 전부 비공개로 두면 호출자가 덮거나 뺄 통로가 없다.

## 증상

- 규약을 지키기로 해 놓고 실제로는 **일곱 자리 중 여섯이 플래그를 안 갖고 있다**
- 소스 전체를 `grep` 해서 "플래그가 있다"를 확인했는데 **런타임 동작은 플래그가 없는 것과 같다**
- 시험을 붙였는데도 통과한다 — 시험이 **문자열에 그 토큰이 있는지**만 보기 때문

## 원인

### 1. 프로세스와 인자가 갈린다

```bash
sudo -u postgres psql -v ON_ERROR_STOP=1 -f install.sql   # ✅ psql 이 받는다
sudo -v ON_ERROR_STOP=1 -u postgres psql -f install.sql   # ❌ sudo 가 먹는다
```

둘 다 소스에는 `ON_ERROR_STOP=1` 이라는 글자가 있다. **줄 단위 텍스트 검사는 실제 argv 를 증명하지 못한다.**

### 2. 규약이 한 개가 아니다

`ON_ERROR_STOP=1` 만으로는 부족하다. `-X`(시작 파일 무시)가 없으면 `~/.psqlrc` 의 한 줄이 종료 코드를 **0 으로 되돌린다** — psqlrc 가 `-f` 입력보다 먼저 돌기 때문이다. **켰다고 믿는데 안 켜진 상태는 안 켠 것보다 나쁘다** → [[psql-exit-code-zero-on-partial-restore]]

### 3. 호출 지점이 늘어난다

새 기능이 같은 CLI 를 부를 때 규약 문서를 읽는다는 보장이 없다. 규약을 **문서로 유지하는 비용**은 호출 지점 수에 비례해 늘고, 언젠가 진다.

## 해결

**조립을 한 모듈에 가두고, 공개 API 는 "연산"으로만 낸다.**

```rust
// psql.rs — 이 파일이 psql 을 부르는 유일한 자리
const SAFE_FLAGS: &[&str] = &["-v", "ON_ERROR_STOP=1", "-X"];  // 비공개, 한 상수
const BINARY: &str = "psql";                                    // 비공개

pub fn run_sql_file(db: &str, path: &Path) -> Result<()> { … }   // 공개는 연산뿐
pub fn scalar_query(db: &str, sql: &str) -> Result<String> { … }
```

지킬 것:

1. **플래그 상수·실행 파일 이름·인자 목록을 전부 비공개로.** 공개 `BINARY` 상수나 호출자가 수정하는 `Vec<String>` 을 남기면 통로가 그대로 남는다.
2. **관련된 플래그는 한 상수에 묶는다.** `ON_ERROR_STOP` 과 `-X` 처럼 하나가 빠지면 다른 하나가 무의미해지는 것들.
3. **셸 경유를 없앤다.** 인자 배열로 직접 프로세스를 띄우면 인용과 `$` 확장 문제가 원리적으로 사라진다.
4. **두 겹으로 잠근다** — ① **인자 순서를 기대값 전체와 비교**하는 단위시험(토큰 존재 여부가 아니라 완성된 argv 를) ② 공용 실행기 **밖에서** 그 명령을 조립하는 자리를 금지하는 통합시험.
5. **접속 대상을 명시한다.** 환경 변수가 기본값을 바꾸는 경우의 영향을 없앤다.

## 남겨 둘 것

전부를 한 방식으로 통일하지 말라. 여러 문장을 한 번에 넘기는 자리를 파일 경유에서 문장 옵션으로 바꾸면, psql 이 그것을 **암묵 단일 트랜잭션**으로 처리해 **일부러 보류해 둔 판단이 조용히 뒤집힌다.** 통일의 대상은 **인자 조립 통로**이지 실행 방식 전부가 아니다.

## 동작 변경은 의도한 것으로 취급하라

오류 중단을 켜는 순간, **종전에 조용히 지나가던 실패가 설치 실패로 드러난다.** 이것은 회귀가 아니라 이 변경의 목적이다. 다만 배포 노트에 반드시 적어야 한다 — 안 적으면 "새 버전이 설치를 깨뜨렸다"로 보고된다.

# 점유(lease)를 별도 저장하지 말고 원장에서 파생한다

> **TL;DR**: "작업이 끝났는가"(원장)와 "누가 점유 중인가"(guard)를 **둘 다 저장하면** 종료 경로마다 반납 코드가 필요하고 **반드시 빠뜨린다**. 점유 여부를 원장에서 유도하면(`미완결 AND 활성 AND 만료 전`) terminal이 되는 순간 **자동으로 해제**되고 반납 코드가 사라진다. lease의 원래 이점이 "명시적 해제에 의존하지 않는 것"이라는 점과 일치한다.

---

## 증상

작업이 성공/실패로 끝났는데도 해당 리소스가 **lease 만료 시각까지 잠긴다.**

```
15:41  작업 A → rolled_back 확정
15:44  같은 호스트에 작업 B 생성 시도 → "다른 작업이 점유 중" 거부
       (guard.lease_expires_at 이 아직 3분 넘게 살아 있음)
```

작업 하나가 끝날 때마다 그 리소스가 lease TTL(예: 15분) 동안 묶이는 셈이다.

## 원인

같은 사실을 두 곳에 저장했다.

| 저장 위치 | 값 | 동기화 필요? |
|---|---|---|
| `operations.result` | 작업이 끝났는가 | — |
| `resource_guard.lease_id`, `lease_expires_at` | 누가 점유 중인가 | **위와 동기화 필요** |

그래서 **작업을 끝내는 모든 경로**가 lease를 해제해야 하는데, 종료 경로는 하나가 아니다:

```
완료 CAS  /  롤백 정착  /  강제 해제(unlock)  ...
```

세 경로 어디에도 해제가 없었고, 고치려다 **한 번 더 빠뜨렸다** — 완료 경로만 고쳤는데 실측에서 문제를 일으킨 경로는 롤백 정착이었다. 경로가 늘어날 때마다 같은 실수가 반복된다.

## 해결: 동기화할 대상 자체를 없앤다

점유를 **저장하지 않고 유도**한다.

```sql
-- "이 리소스를 지금 누가 점유 중인가" = 원장에서 파생
SELECT 1 FROM operations
WHERE resource_id = $1
  AND result IS NULL                    -- 아직 끝나지 않았고
  AND automation_state = 'active'        -- 진행 중이며
  AND lease_expires_at > now();          -- lease가 살아 있다
```

효과:

- **terminal이 되면 `result`가 채워져 자동으로 점유 해제** — 해제 코드가 아예 필요 없다
- 프로세스가 죽어 방치되면 그 작업 행의 lease 만료로 해제된다 — **표준 lease 안전성은 유지**된다
- 소유권 회수(탈취) 조건도 자연스럽게 재정의된다: "guard lease가 내 것이거나 만료됨" → **"자기 외에 유효한 활성 작업이 없을 때만"**. 두 조건은 동등하지만 후자는 동기화가 필요 없다

## 업계 근거

- lease의 핵심 이점은 **명시적 해제에 의존하지 않는 것**이다 — 타임아웃 후 기본 상태가 unlocked
- Chubby는 락을 **세션 lease에 매달아** 세션이 죽으면 락도 죽게 한다. **락 상태를 별도로 저장하지 않는다**

"해제 코드를 어디에 넣을까"를 고민하는 순간, 이미 상태를 이중 저장하고 있다는 신호로 읽어야 한다.

## guard 행에 남길 것 / 남기지 말 것

guard 행 자체는 없앨 수 없다. 파생 불가한 역할이 있다.

| 남긴다 (파생 불가) | 없앤다 (파생 가능) |
|---|---|
| **직렬화 지점** — `SELECT ... FOR UPDATE` 대상 | ~~현재 점유자 id~~ |
| **fencing token 발급기** — 단조 증가 카운터 | ~~점유 만료시각~~ |
| **격리·차단 플래그 보유** | |

★ 직렬화 지점은 반드시 남겨야 한다. 점유 판정을 파생으로 바꿔도 **동시성 제어는 여전히 필요**하다 → [[postgres-write-skew-serialization-row]]

## 안전 계약은 그대로 유지됨을 확인한다

리팩터링이 안전성을 낮추지 않았음을 항목별로 확인한다:

- 리소스 단위 직렬화
- 소유권 회수가 **남의 유효한 점유를 빼앗지 않을 것**
- 토큰 단조성
- 격리 상태 유지

**뮤테이션으로 검증**: 점유 판정에서 terminal 제외 조건을 빼면 "terminal 작업이 즉시 리소스를 반납한다"는 회귀 테스트가 FAIL해야 한다.
